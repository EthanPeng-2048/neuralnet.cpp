# 三值量化的「尺度规则 × 粒度」对真实权重的影响（D1 实测）

> **结论先行**：三值化 `w -> q·τ`（`q ∈ {-1,0,+1}`）里，**统计量必须用 absmean（τ = 组内 mean|w|），
> 不能沿用 llama.cpp `TQ1_0` 的 absmax**。三个真实模型（GPT / ViT / CNN）实测一致：
>
> | 模型（权重数） | absmean@row<br>零化率 / 重构误差 / **信息熵** | absmax@row<br>零化率 / 重构误差 / **信息熵** |
> |---|---|---|
> | GPT d128（3.18M） | 32.7% / 50.4% / **1.585 bit** | 77.4% / 61.4% / **0.997 bit** |
> | MNIST ViT d64（198K） | 26.1% / 42.9% / **1.567 bit** | 67.0% / 66.3% / **1.244 bit** |
> | MNIST CNN（108K） | 27.6% / 45.8% / **1.574 bit** | 84.1% / 80.8% / **0.791 bit** |
>
> **关键数字是"信息熵"那一列**：absmean 下三值分布恰好携带 **1.567 ~ 1.585 bit/权重**
> （≈ `log2(3) = 1.585`，即三值编码的理论上限）；absmax 只有 **0.53 ~ 1.29 bit**——
> 用 1.6875 bpw 的存储装不到 1 bit 的信息，**30% ~ 92% 的存储被浪费在"恒为零"的位置上**。
>
> **粒度**是次要变量：absmean 下 `tensor / row / blk256 / blk128 / blk64` 的零化率与重构误差相差
> 都在 2 个百分点以内（per-row 与 per-block 基本同分，per-tensor 略差）。所以**粒度可以按工程需要
> 挑（布局、对齐、内核），质量上不敏感**；统计量则必须选对。

## 2. 方法

对每个权重矩阵（跳过 shape 为 `(n,1)` 的 bias——它不是矩阵乘权重），比较
**2 种统计量 × 5 种粒度 = 10 种配置**：

| 维度 | 取值 |
|---|---|
| 统计量 | `absmean`（τ = 组内 `mean|w|`，BitNet b1.58 的选择）／ `absmax`（τ = 组内 `max|w|`，llama.cpp `TQ1_0` 的选择） |
| 粒度 | `tensor`（整个矩阵）／ `row`（按输出通道）／ `blk256`／`blk128`／`blk64`（按元素序的定长分块） |

量化规则统一为 `q = (w > 0.5τ) ? +1 : (w < -0.5τ ? -1 : 0)`，即 `RoundClip(w/τ, -1, 1)`
（BitNet 的定义；`lroundf(w/τ)` 在 τ>0 时与它等价）。

三个指标：

| 指标 | 定义 | 回答什么 |
|---|---|---|
| `zero%` | 被量成 0 的权重比例 | "多少权重压根没被表示" |
| `relerr%` | `‖W − τq‖_F / ‖W‖_F` | 权重层面的重构误差 |
| `bits` | 三值分布的信息熵 `−Σ p·log2 p` | **这份三值存储实际携带多少信息**（上限 `log2 3 = 1.585`） |
| `outerr%` | `‖(τq)x − Wx‖_F / ‖Wx‖_F`，`x ~ N(0,1)` | 该层输出被扰动多少（矩阵级代理，不含训练适应） |

**为什么加信息熵**：`zero%` 单独看没有意义（"50% 是 0"不说明好坏）。但三值码位的熵有硬上限
`log2 3 = 1.585 bit`，低于它就意味着**存储容量被浪费**。这一列把"零化率"翻译成了可比的容量指标。

## 4. 解读

1. **absmax 把存储容量浪费掉了**。τ 取组内最大值后，阈值 `0.5·max|w|` 落在分布极远处：
   只有"非常大"的权重能成为 ±1，其余全归零。实测零化率 64% ~ 98%，信息熵掉到
   **0.13 ~ 1.29 bit**——付 1.6875 bpw 的存储代价，拿不到 1 bit 的信息。
2. **absmean 恰好命中三值的信息上限**。τ = `mean|w|` 时阈值落在 `0.5·mean|w|`，
   对称分布下约 1/3 的权重被归零、其余均分到 ±1——这正好是三项等概率分布，熵 = `log2 3 = 1.585`。
   三个模型实测 1.567 / 1.574 / 1.585，逐位命中。这不是巧合：absmean 的阈值**自适应地**把权重
   摊到三个码位上，而 absmax 的阈值由单个离群值决定。
3. **粒度不敏感（absmean 下）**。`row` 与 `blk64/128/256` 的零化率、重构误差、熵几乎相同；
   `tensor` 只略差（GPT 上 33.5% vs 32.5% 零化）。**所以粒度应该按工程约束挑，而不是按质量挑。**
4. **llama.cpp 的 `TQ1_0` 选 absmax 有其语境**：它是"事后量化别人训好的 f32 权重"，
   此时没有任何训练去适应量化误差，逐块 absmax 至少能保证**相对**误差有界；而我们做 QAT / 从头训，
   权重会适应量化，此时唯一该关心的是"三值码位的信息容量"，absmean 完胜。
5. **落地含义（对应 `docs/development/21-quantized-weights.md`）**：
   `TQ1_0` 的**编码与解码照抄**（base-3 5-per-byte + 定点 `(s·3^n·3)>>8`），
   但**块内尺度换成 absmean**；又因为 llama.cpp 的 256 块要求行宽整除 256（我们 d_model=64/128、
   MNIST 784/10 都不满足），块粒度取**行**（per-row）：既满足 absmean、又没有整除约束、
   且与 D2 的"行级打包"一致。

## 5. 本实测不能说明什么

- **这不是"最终精度"**：三个模型都是 f32 训练、从未适应三值，所以重构/输出误差的绝对值很大
  （50%+）。这里比较的是**同一条件下的相对优劣**，不是收敛后的质量。
- **不是端到端指标**：没有 perplexity / 准确率。矩阵级代理（随机 x 的输出误差）只能支撑
  "两种规则差多少"的量级判断。真正的结论要等 QAT 训练对比。
- **未覆盖训练动态**：QAT 下权重会向"三值友好"的方向漂移，两种规则的差距可能缩小；
  但 absmax 损失一个数量级信息容量这件事不会因为训练而消失。
- **未覆盖激活**：三值只在权重侧；激活量化（P3，int8）是另一件事。
