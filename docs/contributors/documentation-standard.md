# 文档规范

> **读者**：往本仓写/改任何文档的人（含 AI 编码助手）。本分册定位见 [`README.md`](README.md)。
> 关联：[`../../CONTRIBUTING.md`](../../CONTRIBUTING.md) §7（文档贡献入口）、
> [`../README.md`](../README.md)（分册定位与全仓索引）、机器审查 = `scripts/doc_audit.py`。
> **状态**：现行。

## 0. 一句话

**每篇文档必须回答四件事——写给谁（读者）、结论是什么（一句话）、现在算不算数（状态）、
内容怎么标注（代码示例/API 符号/术语）；写完必须登记进索引，机器审查（`doc_audit.py`）全绿才算完。**

## 1. 分册职责与编号制度

### 1.1 分册职责（读者矩阵）

| 分册 | 读者 | 写什么 |
|------|------|--------|
| `introduction/` `usage/` `development/` | **调用者**（拿库写自己东西的人） | 当前状态：总览、教程、API 手册、扩展指南 |
| `internal/` | **项目开发者**（改库的人） | 设计稿、路线图、盘点、缺陷台账、整改立项 |
| `contributors/` | **贡献者/维护者/agent** | 长期规范与治理：编码规范、踩坑、文档规范、发布规则 |
| `history/` | 项目开发者 | 全仓**唯一**历史归档：演进、勘误、被否决方案、旧数字 |
| `release-notes/` | 调用者 | 版本变更说明（随 tag 一册） |
| `benchmarks/` | 评估者 | 对外性能基准报告（采集时的实测） |
| `../research/` | 想引用结论/核对定义的人 | 研究档案：定义基线 / 实测结论 / 明确标注的 TODO |

判断口径：**"这篇内容是描述产品，还是约束参与方式？"** 描述产品按调用者分册放；
约束参与方式进 `contributors/`；一次性台账进 `internal/`；已成历史的进 `history/`。

### 1.2 编号制度（两种语义，按分册区分）

| 编号语义 | 适用 | 规则 |
|----------|------|------|
| **稳定台账 ID** | `internal/` | 编号=文档唯一 ID，**新增接当前最大号，永不重排**；缺号是历史正常痕迹，不需要解释性重排 |
| **阅读顺序** | `introduction/` `usage/` `development/` | 编号=建议阅读顺序，**必须连续**（01、02、03…不留洞）；新增文档要么排进顺序重排编号，要么无主题名（仅限"独立参考手册"性质） |
| **无编号主题名** | `contributors/` `research/<topic>/` | 长期真源用主题名（`cpp-standards.md`）；编号不携带信息就不编号 |

- 历史编号文件（`development/04-…` 等）已按阅读顺序重排（2026-11-XX）；此后 `development/`
  新增文档接续最大号并保持语义顺序。
- 转发页（"本文只是指针，真源在 X"）**原则上不建**；确有旧链接需要兜底时才建，且必须在
  首屏标注唯一真源。

## 2. 单篇模板（强制）

每篇 `docs/**/*.md`（豁免见 §2.2）**首屏必须有引用块头部**，三要素齐全：

```markdown
# 文档标题

> **读者**：<一句话>。本分册定位见 [`README.md`](README.md)（或分册入口）；
> 历史归档在 [`../history/history.md`](../history/history.md)。
> **一句话结论**：<本文最重要的一件事，带数字/命令/边界，不写空话>。
> **状态**：现行
```

### 2.1 状态词表（封闭集合，审查器校验）

| 状态 | 含义 |
|------|------|
| `现行` | 内容描述当前代码/规则，随代码同步维护 |
| `冻结` | 内容描述一个不再演进但仍然成立的现状（附冻结日期与原因） |
| `TODO` | 内容含未实施设计/未执行实验；**不得被引用为已有证据** |
| `转发页` | 本文只是指针；唯一真源在文内给出 |
| `已归档` | 历史快照，不再维护（正文应迁去 `history/`，此状态仅用于来不及迁的过渡期） |

### 2.2 豁免

`history/history.md`（历史归档，按时间叙事）、`release-notes/v*.md`（随 tag 冻结）、
`benchmarks/*.md`（采集时快照）豁免头部模板；其余一律适用（含本文件）。

## 3. 内容标注（机器审查的对象）

### 3.1 事实三分（写作纪律）

| 类别 | 写法要求 |
|------|----------|
| **机械事实** | 可由代码/实测直接验证；涉及符号/命令/数字的写法须通过 §4 审查 |
| **设计意图** | 用"设计上/意图是/为了…"明示，不得写成效果 |
| **未验证主张** | 效果类主张（"更快""更强"）**必须**给出指向：实测→`../research/` 条目；未测→标 `TODO` 并指向实验计划 |

教训来源：`development/08-rapt-algorithm.md` 曾把设计意图写成效果结论（"只检索语义相关
Token"），2026-11 整改时按本条重写。

### 3.2 代码示例（三类角色，info string 标注）

C++ 代码块的 fence info string 必须声明**角色**：

| 标注 | 含义 | 要求 |
|------|------|------|
| ```` ```cpp example api ```` | 演示公开 API 的可编译示例 | 出现的每个 API 符号必须真实存在且签名匹配（审查器 F 类核对） |
| ```` ```cpp snippet ```` | 概念片段（省略上下文/错误处理，不可直接编译） | 片段内的 API 符号仍必须存在 |
| ```` ```cli ```` | 命令行示例 | 每个 `--flag` 必须在对应可执行文件的解析代码中存在（审查器 D 类核对） |

- 其他语言同理：`python` / `bash` / `cmake` 块标 `` snippet ``（默认）或 `` example ``。
- **无标注 = 默认 `snippet`**（审查器允许省略，但 `api` 角色必须显式声明）。
- 审查器会**提取全部代码块生成复核清单**（`build/doc_audit/code_examples_report.md`），
  按文件/行号列出每段的角色与引用符号核对结果；**符号对得上不等于逻辑对**，示例改动后
  须人工过一遍清单。

### 3.3 API 符号

- 本仓公开符号一律反引号包裹：`` `nn::Model` ``、`` `ComputeEngine::forward` ``；
  不用引号、不裸写。审查器对 `nn::*` 及文档中反引号类名做符号表核对（审查器 E 类）。
- 提到**已删除**的符号/文件/CLI 参数时，须同句写出"已删除/已移除"字样（审查器识别否定语境，
  不报残留）。

### 3.4 历史性记载禁令（唯一归档 = `history/`）

**除 `history/history.md` 外，任何文档与代码注释一律不得出现历史性记载**——
如"xxx 已在 commit `abc1234` 修复"、"2026-10-13 的溢出修复"、"该参数于某日被删除"。<!-- doc-audit: allow H -->
写法一律改写为**当前事实**："当前行为是什么、约束是什么"；变更过程、修复日期、
被删对象的来龙去脉 → [`../history/history.md`](../history/history.md)。

**时点记录文档豁免**（它们本身就是记录，按版本/采集时点冻结）：
`history/` 本体、`release-notes/v*.md`、`benchmarks/*.md`、`research/` 报告、
`contributors/release-requirements.md` 的实跑记录节。

允许的两类边界写法：
- **状态标记**：台账里的 `✅ 已实施（2026-10-20）` 是进度状态，不是叙事（`internal/` 允许）；
- **兼容性契约**："与旧 checkpoint 参数布局逐位一致""缺键不回落"描述的是**当前行为**
  对旧文件的承诺，不是历史；但不得展开"当初为什么、当时怎么改"。

### 3.5 术语

- 统一用**代码里的名字**称物：类型名/文件名/CLI 参数名照抄代码，不自造别名。
- 中英混排规则：专有名词（Vulkan、RoPE、GPT）保留原文；通用技术词首次出现给中英对照，
  后文统一用中文。

## 4. 索引与生命周期义务

1. **登记义务**：新增/删除 `docs/**/*.md` 必须同步两处——分册 `README.md` 索引 +
   [`../README.md`](../README.md) 总索引（审查器 E 类核对，漏登记即 FAIL）。
2. **归档义务**：演进叙事（"当初为什么、旧数字、被否决方案"）一律进
   [`../history/history.md`](../history/history.md)；索引/规范/台账文件里**不得**承载叙事段落。
   **历史性记载禁令见 §3.4**：`history/` 之外（含代码注释）不得出现
   "已在 commit xxx 修复"式记载（引述禁令本身不计）；机器审查 [H] 类兜底。<!-- doc-audit: allow H -->
3. **同步义务**：改了 API/CLI/文件名，同 PR 内更新引用它的文档（审查器 A/D/E/F 类兜底）。
4. **引用口径**：引用本仓结论/规范时**连出处一起引用**（文档名 + 章节），不转述。

## 5. 机器审查（`scripts/doc_audit.py`）

```bash
python scripts/doc_audit.py            # 全量检查，FAIL 时 exit 1
python scripts/doc_audit.py --report   # 另生成 build/doc_audit/code_examples_report.md 代码示例复核清单
```

| 类 | 检查项 | 失败级别 |
|----|--------|----------|
| A | 文档引用的文件/链接目标存在（历史白名单豁免已删文件） | FAIL |
| B | 已删除符号无正向残留（识别"已删除"否定语境） | FAIL |
| C | 数字型断言（N 个 virtual / N/N 绿）披露待核 | WARN |
| D | `--flag` 在代码中存在（外部工具/已删/计划中三张白名单） | FAIL |
| E | 头部模板齐全 + 状态词合法 + **索引登记**（分册 README + 总索引） | FAIL |
| F | `nn::` 符号与反引号类名在 `include/`/`src/` 存在；测试名在 CMake/src 存在 | FAIL |
| G | 代码示例清单：提取全部代码块 → 复核报告（角色标注 + 符号核对） | FAIL（标注违规）/ 报告供人工复核 |
| H | **历史性记载**：`history/` 之外的 commit hash 引用、"已在…修复"、日期+变更动作叙事（§3.4；示例行以 `<!-- doc-audit: allow H -->` 豁免） | FAIL |<!-- doc-audit: allow H -->

- 白名单（历史文件/已删符号/外部 CLI/历史测试名）维护在脚本顶部，**带注释说明每一项的来历**。
- 本地口径：改文档必跑；CI 口径见 [`../../CONTRIBUTING.md`](../../CONTRIBUTING.md) §5。
- `scripts/doc_audit.py` 是文档审计的**唯一实现**（八类检查以本文档 §5 为准）。
