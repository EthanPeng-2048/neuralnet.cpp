# neuralnet.cpp v1.10.0-rc0.1 Release Notes（预发布候选）

> **发布范围**：`v1.10.0-rc0`（`a176d8e`，2026-10-20）→ `v1.10.0-rc0.1`（`dev/lifetime_refresh`，2026-10-21）。
> **主题**：**P2b 训练工厂**——数据集显式定义**样本**（不再以 step 为单位）、数据集**直接接入** `TextTrainer`；
> `TrainingSession` 持有训练状态；`text_train`/`mnist_train` 完成 Session 迁移。
> **兼容性**：**有破坏性变更**（数据集/训练 API 层）：`Dataset::load_text(bool)` → `load_text(DatasetSubset)`；
> `DatasetIdentity.num_windows` → `num_samples`（断点键 `dataset_windows` → `dataset_samples`，**旧键兼容读**）；
> 训练循环不再由 CLI 实现（`cli/text_train_loop.hpp` 只留 hooks）。文件格式 v8 与版本号**不变**。
> **定位**：`rc0` 后续预发布候选，只覆盖 P2b 训练工厂/样本层；完整四编译器矩阵与 Linux+850M 权威口径
> **未在本次重跑**（沿用 v1.9.0 记录与 rc0 的 clang 口径）。正式版仍需按
> [`docs/contributors/release-requirements.md`](../contributors/release-requirements.md) §1–§3 全量重跑。

## 0. 亮点速览（TL;DR）

| 方向 | 变化 | 收益 |
|---|---|---|
| **样本概念** | 数据集存储单位 = **doc**；训练单位 = **sample**（文本 = `seq_len` 窗口）；`step = ceil(样本数 / batch_size)` 是**派生量** | "样本"不再与"step"混用：数据集/断点身份记样本数，训练步数由 batch 派生；`dataset_samples_test` 锁住逐位约定 |
| **数据集直连训练工厂** | 新 `nn::TextTrainer`：`create(TrainingSession, Dataset, TextTrainConfig)` → `fit()`；内部建样本集、跑 epoch×step、装断点状态 | 训练入口从 ~400 行手工接线降到"打开数据集 + 建 Session + create + fit"；算法循环回到库层、可被测试/库外复用 |
| **训练状态收编** | `TrainingSession` 持有 `nn::TrainState`；唯一装配函数 `nn::make_text_train_state` | "计数器/配方/数据集身份"与 Model/Optimizer 同生共死；CLI 不再手工拼状态段 |
| **CLI 简化** | `text_train.cpp` 删掉 corpus 加载/切窗/batch 填充；`cli/text_train_loop.hpp` 只剩 CLI hooks（梯度日志/探针/断点）；`mnist_train` 迁到 Session | 入口只留"配置 + 构建 + 产物 + 退出码"；行为文案与顺序保持 P1-1 锚 |
| **配方单一真源** | `nn::TextTrainConfig`（库层）；CLI `TrainConfig` 继承它；`lr_scheduler.hpp` 上收库层 | 不再出现 CLI 与训练工厂两份默认值各自漂移 |

## 1. 样本概念（`dataset_samples.hpp`）

```text
存储单位 = doc（.nndataset 里一行文本）
训练单位 = sample（一个 seq_len 滑动窗口，可跨 doc）
step     = ceil(sample_count / batch_size)   ← 派生量，不写进数据集格式
```

- `nn::DatasetSubset{Train, Test}`：`Dataset::load_text(subset)`、`doc_count(subset)`、
  `text_doc(subset, index)`（存储单位访问）。
- `nn::TextWindowConfig{seq_len, stride, pad_id}`：窗口化策略（训练策略，不进文件格式）。
- `nn::TextSample`：样本视图（`tokens/doc_ids/loss_mask/valid_len/offset`）。
- `nn::TextSampleSet::create(dataset, subset, cfg)`：一次完成切窗 + 元数据；
  `sample_count()`、`sample(i)`、`steps_per_epoch(batch_size)`、`make_batch(indices, out)`。
- `nn::TextSampleBatch`：`input` 矩阵 `(seq_len, batch)` + **batch-major** 扁平
  `flat_targets`/`flat_mask`/`doc_ids` + `valid_tokens`。逐位约定（与旧 CLI 循环一致）：
  - `x[t] = token_flow[offset+t]`，`y[t] = token_flow[offset+t+1]`（目标 = 下一 token）；
  - 位置参与 loss ⇔ `t+1 < valid_len && loss_mask[offset+t+1]`（mask 按**目标**位置）；
  - PAD 位置 `x/y = pad_id`、`flat_mask = 0`、`doc_ids = 0`；末批可不满。

## 2. 训练工厂（`text_trainer.hpp`）

```cpp
auto dataset = NN_UNWRAP(nn::Dataset::open("train.nndataset"));
auto session = NN_UNWRAP(nn::TrainingSession::create(std::move(model), session_cfg));
nn::TextTrainConfig recipe;                     // 训练配方唯一真源
auto trainer = NN_UNWRAP(nn::TextTrainer::create(std::move(session), dataset, recipe));
auto report  = NN_UNWRAP(trainer.fit());        // 返回 TextTrainReport
```

- `TextTrainer` 拥有：训练/测试 `TextSampleSet`、`CrossEntropyLoss`（precision = 配方）、
  shuffle、梯度累积/裁剪、lr 调度（epoch / step_cosine）、非阻塞 loss 回读、测试评估、
  断点状态装配。
- **配方单一真源（P0 校验）**：优化器侧字段（`optimizer`/`lr`/`weight_decay`/`beta1`/
  `beta2`/`precision`/`max_norm`）的真源是 `TrainingSession` 的 `TrainingConfig`；
  `TextTrainConfig` 中同名字段必须与之完全一致，否则 `create` fail-fast（防"实际用 Session
  的 lr、日志/断点写配方 lr"的静默错训）。推荐起步 = `nn::make_text_train_config(session)`。
- 其余前置校验：`batch_size>0`、`accum_steps>0`、`log_interval>0`（0 会在进度打印时除零）、
  `start_epoch>=0` 且 `<=epochs`、`start_step<steps`、训练样本非空、窗口网格/词表 pad 一致。
- 编排 **不归** Trainer：模型构建/恢复/产物保存/CLI 文案（`TextTrainerHooks`：`out/err`、
  `on_batch_ready`、`on_probe_check`、`on_update`、`on_checkpoint`、`on_phase`）。
  hooks 的契约 = 只活到 `fit()` 返回（`fit` 结束时清空，避免捕获的局部引用被下一次调用复用）。
- 高性能入口：调用方已切好样本集时用
  `create(session, train_set, std::optional<TextSampleSet> test, cfg, hooks)`
  （CLI 走这条，避免同一数据集重复加载/哈希）。
- 结果：`TextTrainReport{seconds, elapsed_ns, steps_executed, samples_executed,
  ckpt_failures, abort_code, final_lr, final_epoch, final_step_in_epoch}`。

## 3. `TrainingSession` / 配方 / 断点状态

- `TrainingSession` 新增持有 `TrainState`：`train_state()/set_train_state()`（写入方 = 训练工厂；
  Session 只负责生命周期）；`fit()` 结束把计数器推进到**真实下一步位置**——正常跑完 =
  `(epochs, 0)`，`--max-steps` 提前停 = 实际停止位置（不再谎报"训练已完成"）；探针中止时
  不更新 Session 状态（`TextTrainReport.final_epoch/final_step_in_epoch` 仍报告实际位置）。
- `nn::make_text_train_state(cfg, identity, steps_per_epoch, epoch, step_done, lr, optimizer_step)`
  是状态装配**唯一实现**（计数器 epoch 边界归一化、global_step、配方、数据集身份、优化器 `t`）。
- `nn::TextTrainConfig`（`text_train_config.hpp`）= 数据网格/调度/记录配方；优化器侧字段与
  Session 同源（见 §2 的 P0 校验）。CLI `TrainConfig` 继承它，只多入口字段（数据集/保存/恢复/
  模型结构/GPU/flush/checkpoint/offload）。
- `lr_scheduler.hpp` 上收库层（`nn::LrScheduleConfig` / `nn::StepLrScheduleConfig` /
  `nn::compute_epoch_lr` / `nn::compute_step_lr`）；`cli/cli_lr_scheduler.hpp` 变转发头（`nn::cli::*` 保留）。
- **断点状态段**：`DatasetIdentity.num_windows → num_samples`，键 `dataset_windows → dataset_samples`；
  读盘时旧键回退；v8 文件版本不变。`dataset_mismatch_reason` 文案改为"样本数"。

## 4. CLI 迁移

| 入口 | 变化 |
|---|---|
| `text_train` | `Dataset` → `TextSampleSet`（train/test）→ 模型构建/resume → `TrainingSession` → `TextTrainer`；`text_train.cpp` 不再手工拼 token 流/切窗/填 batch；`cli/text_train_loop.hpp` 只剩 CLI hooks（`--grad-log`、`NN_NAN_TRACE`、`NN_MEM_STATS`、定期 `.nnckpt` 写盘） |
| `mnist_train` | 自由工厂 `create_optimizer` + `unique_ptr<Optimizer>` → `TrainingSession`（Model + Optimizer 同生共死）；训练/评估/保存逻辑与输出文案不变 |
| `--resume` | 语义不变：状态段仍是权威（形状/配方/计数器），数据集身份门禁按 `num_samples` / `steps_per_epoch` 比较；旧 rc0 断点可读 |

行为语义（与旧 CLI 对齐，已写进 `text_trainer_test`/`dataset_samples_test`）：

- **空 test 子集**（合法文件：test 全为空 doc）= 无 test ⇒ 打印 `样本数: 0` 并跳过评估，训练继续；
- **测试评估失败**（GPU 瞬时错误等）⇒ 打印到 `hooks.err` 后放弃本轮剩余 test batch，训练继续并照常保存最终 `.nnmodel`（不会因评估失败丢整轮训练）；
- `--max-steps` / `start_step` 提前停 ⇒ Session 的 `TrainState` 记录**真实下一步位置**，不写 `(epochs,0)`。

## 5. 迁移表（v1.10.0-rc0 → v1.10.0-rc0.1）

| rc0 | rc0.1 |
|---|---|
| `dataset.load_text(false/true)` | `dataset.load_text(nn::DatasetSubset::Train / ::Test)` |
| `dataset.info().num_docs`（只有 doc 数） | 另加 `dataset.doc_count(subset)` / `dataset.text_doc(subset, i)`（存储单位） |
| 手工 `window_offsets` + 逐 step 填充 `Matrix` | `nn::TextSampleSet::create(dataset, subset, {seq_len, stride, pad_id})` + `make_batch(indices, batch)` |
| "样本数" = `window_offsets.size()`（散落在 CLI） | `sample_count()`；`steps_per_epoch(batch_size)` 是派生量 |
| `DatasetIdentity::num_windows` / 断点键 `dataset_windows` | `DatasetIdentity::num_samples` / 键 `dataset_samples`（旧键兼容读） |
| CLI 内的 epoch×step 循环 | `nn::TextTrainer::fit()`（库层）；CLI 只装 hooks |
| 手工 `create_optimizer` + 保证析构顺序 | `nn::TrainingSession`（Model + Optimizer + TrainState） |
| `nn::cli::make_train_state(...)`（CLI 头） | `nn::make_text_train_state(...)`（库层，唯一实现） |
| `nn::cli::LrScheduleConfig` / `compute_epoch_lr` | `nn::LrScheduleConfig` / `nn::compute_epoch_lr`（`nn::cli::*` 旧名转发保留） |
| `TrainConfig` 自带全部配方字段 | `TrainConfig : nn::TextTrainConfig`（配方继承，防两份默认值漂移） |

### 6.1 独立评审收口（rc0.1 内已修）

- **P0**：`TextTrainer` 与 `TrainingSession` 的优化器侧配方（optimizer/lr/weight_decay/
  beta/precision/max_norm）从"只校验 clip"改为**逐项校验** + `nn::make_text_train_config(session)`
  派生入口；`log_interval=0` 等除零/边界参数前置 fail-fast。
- **P1**：`--max-steps` 提前停时 `TrainState` 写真实下一步位置（新增
  `TextTrainReport.final_epoch/final_step_in_epoch`）；测试评估失败恢复"打印后继续训练"的旧语义；
  空 test 子集 = 跳过评估；hooks 生命周期 = 到 `fit()` 返回；CLI 实际走的高性能样本集入口
  补单测；AGENTS/usage 的 resume 示例修正。
- 其余 P2 级建议（种子 API、通用 Step 协议、tokenizer 去重、更多 assistant 掩码组合用例）
  留 rc0.2/正式版前，已在代码注释标注契约。

## 7. 已知限制 / 未覆盖（rc0.1 明示）
> 发布标识：release 名称 **v1.10.0-rc0.1**，git tag **`v1.10.rc0.1`**。

1. **流式 DataLoader 仍未做**（P2-4 后半）：`TextSampleSet` 仍把子集整段物化到 `TextCorpus`
   （token_flow/doc_ids/loss_mask），超大语料的内存曲线问题与 rc0 相同。
2. **`InferenceSession` / `RLTrainingSession` 仍为占位**（docs/internal/29 §6/§7）。
3. **`create_optimizer` 自由工厂签名未收口**（D7：`unique_ptr`/`nullptr`），留待下个破坏性窗口；
   `Session` 已覆盖训练路径，CLI 不再使用自由工厂。
4. **`TextTrainer` 目前只服务文本/GPT 任务**（内置 sparse-CE）；MNIST/自定义任务的通用 Step
   协议未抽象（触发条件 = 出现第二类需要同一循环的任务）。
5. **断点旧键兼容是单向的**：rc0.1 断点写 `dataset_samples`，rc0 二进制读不到（会得 0 ⇒ 身份对比失败）；
   升级方向（rc0 → rc0.1）完全可读。v8 文件版本号未变。
6. **矩阵覆盖**：GPU ctest 在本机 **NVIDIA CMP 40HX / 驱动 616.92** 验证；Linux + 850M、
   libc++/libstdc++、MSVC 本轮未重跑（沿用 v1.9.0/rc0 记录）。`layer_bench` 配对 A/B 未重跑
   （本轮无 kernel 改动）。
7. **`mnist_train` 的优化器侧训练状态未接入 `.nnckpt`**（mnist 路径本来就没有优化器状态段）；
   文本路径的断点语义不变。
