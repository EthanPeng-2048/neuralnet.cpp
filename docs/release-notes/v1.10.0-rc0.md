# neuralnet.cpp v1.10.0-rc0 Release Notes（预发布候选）

> **发布范围**：`v1.9.0`（`d7b4c4a`，2026-10-18）→ `v1.10.0-rc0`（`dev/lifetime_refresh`，2026-10-20）。
> **主题**：**对象生命周期 v3（设备域模型）** + **`TrainingSession` 训练生命周期容器** + **`GpuBackend` 确定性回收**。
> **兼容性**：**有破坏性变更**——`Tensor` 不再保存引擎身份（`engine_id()` / `bound()` 删除）；`ComputeEngine::id()`、`GpuBackend::instance()`、`NN_BIND_DEBUG` 删除；GPU 引擎默认拒绝 CPU 张量操作数。迁移见 §5。
> **定位**：`rc0` 是 `dev/lifetime_refresh` 分支的预发布候选。P2b（CLI 全面切到 `TrainingSession` + 训练状态收编）**不在本次**，见 §7。

## 0. 亮点速览（TL;DR）

| 方向 | 变化 | 收益 |
|---|---|---|
| 生命周期 v3 | 删除 8 B 引擎身份字段（`EngineId`）与整套传播机制（`stamp_` / `adopt` / `bound` / `NN_BIND_DEBUG`）；设备域从**存储**派生（CPU → `kHostDomain`，GPU → backend 标识，空 → 0） | 减少一个概念：张量不需要知道"谁创建了我"，只需要知道"现在在哪块设备上"；机制点 101 → 42，净代码约 −120 行；`sizeof(Tensor)` 64 → **56 B**（GPU 构建 88 → **80 B**） |
| 入口检查 | 每个 public NVI 入口**逐个操作数**比较设备域（旧 `bind_check_` 只比较操作数之间，单操作数入口可让外来 GPU 张量进入任意引擎） | 修复 D1：跨 backend 张量不再静默别名/UB，而是带 `source_location` + 形状 + 迁移提示的 `Result` 错误 |
| CPU/GPU 统一语义 | GPU 引擎拒绝 CPU 张量操作数（显式 `import` → `to_matrix` 是唯一跨域通道）；删除 GPU impl 的 CPU 回退分支 | 推理/训练不再有"隐式上传"的语义分歧；CPU 与 GPU 走同一条域规则 |
| `TrainingSession`（P2a） | 新头 `training_session.hpp`：拥有 `Model` + `Optimizer` + 训练计数器，成员声明顺序保证 optimizer 先析构 | D3 的结构性修复：`Optimizer::params_/grads_` 的非拥有 `TensorRef` 永远有效（UAF 不可能发生） |
| `GpuBackend` 回收 | `shared()` 改 **weak 缓存 + mutex**；删除 `instance()` | 最后一个使用者释放后 Vulkan 资源**确定性回收**（旧实现 static 强引用活到进程退出）；再次 `shared()` 重建 |
| activation offload | 状态机 fail-fast + forward 入口 `discard()` 作废通道 + `f16/t1_58` 组合配置期拒绝 | 推理/评估路径"未配对 backward"不再静默导入上一轮 slab（D4）；`f16` 激活 restore 后变 `f32` 的精度漂移被拒绝 |
| 录制段安全 | `ExprSegment` 改持 `shared_ptr<ComputeEngine>`；GPU `end_expr` 无录制时明确报错 | 作用域内释放最后一个引擎句柄不再 UAF（D6）；跨线程 begin/end 从静默 no-op 变为可诊断错误 |

## 1. 生命周期 v3：设备域模型

### 1.1 目标模型

```text
Tensor 只拥有存储：
  CPU 存储  → 域 = kHostDomain（进程常量；CPU 引擎无状态、共享宿主内存）
  GPU 存储  → 域 = 其 GpuBuffer 的 backend 标识（buffer 持 shared_ptr<GpuBackend>
              keepalive ⇒ 张量存活期内地址不被新 backend 复用）
  空/无效   → 0（唯一豁免，交由各入口既有的无效/形状检查拒绝）

ComputeEngine 在派生类构造时写入本引擎域（非虚函数，虚表口径 52 方法不变）；
每个 public 入口逐个操作数比较 t.device_domain_() == domain_。
```

`import` 是唯一跨域入口：CPU → GPU 上载；同域 = 别名/cast；GPU 异 backend 或
GPU → CPU（应走 `to_matrix`）= 明确错误。

### 1.2 失败语义

| 场景 | v1.10.0-rc0 行为 |
|---|---|
| 张量活过引擎（含 GPU） | 安全（GPU 由存储 keepalive 保证） |
| 跨 CPU 引擎使用张量 | 允许（同一宿主域；CPU 引擎无状态） |
| GPU 张量进入不同 backend 的引擎 | `Result` 错误：跨 GPU backend，提示先 `to_matrix` 落宿主 |
| CPU 张量进入 GPU 引擎 op | `Result` 错误：提示先 `engine.import(t)` |
| GPU 张量进入 CPU 引擎 op | `Result` 错误：提示先 `engine.to_matrix(t)` |
| 跨 backend `import` | `Result` 错误（提示先落 CPU） |
| 空张量参与运算 | 域检查跳过（0 豁免），由既有无效/形状检查拒绝 |

### 1.3 删除清单

- `include/neuralnet.cpp/core_engine_id.hpp`、core_engine_lease.hpp（整体删除）；
- `EngineId`、`ComputeEngine::id()`、`Tensor::engine_id()`、`Tensor::bound()`；
- `ComputeEngine` 的 `stamp_` / `adopt` 出生绑定通道（及 `nn::dsl` friend）；
- `NN_BIND_DEBUG` 行为开关与其 CI 第二轮 ctest；
- GPU impl 的 CPU 回退分支（`cast` / `copy_from` / `clone` / `copy_into` / `cast_into`）。

## 2. `TrainingSession`（P2a）

新头文件 `include/neuralnet.cpp/training_session.hpp`（`nn.hpp` / `train.hpp` 已转发）：

```cpp
nn::TrainingConfig cfg;
cfg.optimizer = "adamw"; cfg.lr = 1e-3f; cfg.weight_decay = 0.01f;
cfg.clip_grad_norm = 1.0f;                       // 0 = 不裁剪

auto session = NN_UNWRAP(nn::TrainingSession::create(std::move(model), cfg));
NN_UNWRAP(session.zero_grad());
auto logits = NN_UNWRAP(session.model().forward(x));
/* ... loss / backward（由调用方组合） ... */
NN_UNWRAP(session.clip_grads());
NN_UNWRAP(session.step());                       // optimizer.step() + step_count++
```

所有权不变式（ASan 下测试覆盖）：

1. `model_` 声明在 `opt_` 之前 ⇒ **optimizer 先于 Model 析构**（`TensorRef` 永悬空）；
2. Session 不可拷贝、可移动（Layer 对象在堆上，移动后 `TensorRef` 仍有效）；
3. `Model` 保持纯值对象——推理可直接用 `Model`，不需要 Session；
4. **Loss / 数据集 / epoch / CLI / 日志不归 Session**（防 god object，见 docs/internal/29 §4）。

自由工厂 `create_optimizer(name, engine, params, grads, ...)` **保留**：调用方必须保证
"optimizer 在其参数所有者存活期内销毁"；需要结构保证时用 `TrainingSession`。

## 3. `GpuBackend` 确定性回收

```cpp
static std::shared_ptr<GpuBackend> shared();   // weak 缓存 + mutex；全部释放后回收
static std::shared_ptr<GpuBackend> create();   // 独立实例（测试/多设备）
// instance() 已删除（16 处调用点迁移为持有 shared() 的 shared_ptr）
```

行为：有活使用者时复用同一实例；最后一个使用者释放后 backend 与 Vulkan 资源按序析构；
下一次 `shared()` 重新创建（**不**自动初始化设备，调用方仍需 `initialize()`）。
`GpuBuffer` 的 backend keepalive 保证"张量存活期内 backend 不析构、地址不复用"。

## 5. 迁移表（v1.9.0 → v1.10.0-rc0）

| v1.9.0 | v1.10.0-rc0 |
|---|---|
| `t.engine_id()` / `t.bound()` | **删除**。需要"能否在本引擎使用"时改用操作结果（`Result`）；不要从张量反查引擎 |
| `engine->id()` | **删除**（身份概念不存在）；诊断用 `engine->domain()` |
| `GpuBackend::instance()` | `auto owner = GpuBackend::shared(); GpuBackend& backend = *owner;`（owner 必须存活到使用者结束） |
| `gpu_engine.xxx(cpu_tensor)`（隐式上传） | 显式 `auto t = NN_UNWRAP(gpu_engine.import(cpu_tensor));` 再调用 |
| GPU 结果回宿主：`cpu_engine.xxx(gpu_tensor)` | `auto m = NN_UNWRAP(gpu_engine.to_matrix(gpu_tensor));`（`to_matrix` 本就是引擎入口） |
| `NN_BIND_DEBUG=1 ctest` | 删除；域检查已是**默认入口检查** |
| `ExprSegment seg(engine)`（裸引用） | `nn::ExprSegment seg(engine_owner)`（持 `shared_ptr<ComputeEngine>`；录制段内引擎不会析构） |
| 自定义 `ComputeEngine` 子类构造 | 基类构造从 `ComputeEngine()` 改为 `ComputeEngine(DomainId)`：`CpuEngine` 传 `kHostDomain`，`GpuEngine` 传 `backend->identity()` |
| `GpuEngine::to_matrix(跨 backend 张量)` | 明确 `Result` 错误（v3 前会读外来 `VkBuffer` = UB）；`to_matrix` 只接受本引擎域 GPU 张量与宿主域 CPU 张量 |
| 自由工厂 + 手工保证析构顺序 | 推荐 `TrainingSession`（`Model` + `Optimizer` 同生共死）；自由工厂仍可用，契约不变并在文档写明 |
| `Model` 上未绑定引擎的 `abort` 路径 | 新增 `Model::engine_bound()` 只读查询；`TrainingSession::create` 返回 `Result` 错误 |
| `sizeof(Tensor)` = 64 B（CPU）/ 88 B（GPU） | **56 B / 80 B**（少 8 B 身份字段；拷贝少一次 8 B 复制） |

## 7. 已知限制 / 未覆盖（rc0 明示）

> 发布标识：release 名称 **v1.10.0-rc0**，git tag **`v1.10.rc0`**（用户裁定）。

1. **P2b 未做**：`text_train` / `mnist_train` 仍用自由工厂 + 手工训练状态；`TrainingSession::save/load_state` 未实现。计划在正式版前完成，并与 §5 的迁移表一起复核 CLI 端到端逐字节一致。
2. **`create_optimizer` 签名未收口**（仍 `unique_ptr`/`nullptr`）：改名/返回 `Result` 属破坏性变更，留待下一个破坏性窗口。
3. **`Layer::BindingState` 三态**、`nn::TensorRef` 与 `dsl::TensorRef` 重名未处理（D9，低风险）。
4. **GPU 设备口径差异**：本机验证用 RTX 2060 SUPER；`scan_bitwise_test` / f16 权威覆盖仍以 Linux + 850M / 40HX 为准（本次分支未在 850M/40HX 上复跑）。
5. **activation offload 与混合精度/三值**：本 rc 选择**配置期拒绝**（最短正确路径），并新增 CPU 引擎 fail-fast（CLI/Session/库三层）；精度协议化（slab 按存储精度记账）留作后续立项。**offload + checkpoint 混合模式仍无独立回归用例**（只有各自单模式测试）。
6. **`GpuBackend::shared()` 非线程安全初始化设备**：weak 缓存本身有 mutex；`initialize()` 仍有既有 `init_mutex_`，多线程首次 `shared()` 后再 `initialize()` 的行为与 v1.9 相同。
