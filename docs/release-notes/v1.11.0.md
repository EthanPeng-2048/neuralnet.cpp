# neuralnet.cpp v1.11.0 Release Notes

> **发布范围**：`v1.10.0`（tag `v1.10.0`，2026-10-21）→ `v1.11.0`（tag `v1.11.0`）。
> **主题**：**TrainingSession 单步协议（`train_step`）与 global/micro batch 语义**（docs/internal/30）——
> 梯度累积上收 Session、按 global batch 有效单位归一化、运行态 `TrainState` 归 `TextTrainer`。
> **兼容性**：**有破坏性变更**（API 与 CLI 行为）——`TrainingSession::train_state()` / `set_train_state()`
> 删除（运行态移至 `TextTrainer`）；`--batch-size` / `TextTrainConfig.batch_size` 从 **micro-batch** 改为
> **global batch**（同名参数行为变化，见 §4）；step 计数统一为 optimizer update。**模型文件格式 v8 不变**；
> **v1.10.0 写出的 `.nnckpt` 可继续 `--resume` 续训**（§5）。迁移见 §4。
> **修正的正确性缺陷**：v1.10.0 在 `--accum-steps > 1` 时对每个 micro 梯度乘 `1/accum_steps`
> （“micro 均值之均值”），当 loss_mask 使各 micro 有效 token 数不同或末批不满时会偏离理论 global batch
> 目标函数；本版按 `gradient_units / normalization_units` 精确归一化（§3）。默认 `accum=1` 路径不受该缺陷影响。

---

## 1. 动机与定位

v1.10.0 的 `TrainingSession` 只提供 `zero_grad()` / `clip_grads()` / `step()` 低层原语，同时持有含
epoch、lr 曲线、batch/accum 与数据集身份的完整 `TrainState`；训练管线（zero_grad → forward/loss/
backward → clip → step）由 `TextTrainer` 与 `mnist_train` 各自手写，梯度累积的归一化也在循环侧。
本版把“**一次参数更新**”收进 Session，形成稳定边界（docs/internal/30）：

- `TrainingSession` 是模型+优化器的训练生命周期容器，也是**一次 update 的执行器**；
- 接收已装配的 **micro-batch**，经任务 Step 回调完成 forward/loss/backward，内部维护梯度累积，
  在 update 边界执行归一化、裁剪、`optimizer.step()`、`zero_grad`；
- 不拥有数据集、样本顺序、epoch、lr 曲线、评估、断点策略——这些仍在 `TextTrainer`（Run Driver）。

## 2. `train_step` 单步协议

```cpp
struct TrainingStepOutput
{
    Tensor grad;                    // 对模型输出的梯度
    std::size_t gradient_units;     // grad 已采用的归一化单位数
    Tensor loss_sum;                // 可选：设备侧 loss 分子
    std::size_t loss_units = 0;
};

struct TrainingStepOptions
{
    std::optional<Scalar> lr;
    Scalar clip_grad_norm = 0;
    std::size_t normalization_units = 0;   // 整个 update 的归一化单位（必填 > 0）
    bool force_update = false;             // 尾部 micro-step 用，避免梯度悬挂
    std::function<Result<bool>()> before_update;  // true = 中止且不更新
    std::function<Result<void>()> after_update;   // step 后、zero_grad 前
};

struct TrainingStepReport
{
    bool parameters_updated = false;   // 本次 micro-step 是否落在 update 边界
    std::uint64_t optimizer_step = 0;
    std::size_t microsteps_accumulated = 0;
    Tensor loss_sum;                   // 可异步回读的 loss 汇总
    std::size_t loss_units = 0;
};

// 用法：
auto report = NN_UNWRAP(session.train_step(
    micro_batch, opts,
    [&](nn::Model& model, nn::ComputeEngine& engine, const nn::Tensor& input)
        -> nn::Result<nn::TrainingStepOutput> {
        // forward → sparse-CE loss → backward(loss)；返回 grad 已按 gradient_units 归一化
    }));
```

低层原语 `zero_grad()` / `clip_grads()` / `step()` **保留**（自定义循环 / `mnist_train` 仍用）；
新增 `reset_accumulation()`（失败后显式丢弃不完整 update）与只读 `state()`（`TrainingSessionState`：
current_lr / optimizer_step / 累积 microsteps / pending loss）。

## 3. Global-batch 归一化契约（正确性修正）

禁止把各 micro 的均值简单乘 `1/grad_accum_steps`。统一契约：

- Run Driver 在拆 micro-batch 前算出本次 update 的 `normalization_units`（文本 sparse-CE = 全
  global batch 有效 token 数，`TextSampleSet::valid_target_count()` 不物化 batch 即可得）；
- Step 回调返回的梯度按其 `gradient_units` 归一化；
- Session 对每个 micro 梯度缩放 `gradient_units / normalization_units` 后 `model.backward()`；
- 等价于所有 micro-batch 按同一有效单位总和归一化，与“逐样本求和后一次归一”严格等价；
- `normalization_units == 0` 明确报错，不执行无意义参数更新。

`TextSample.loss_mask` 是“哪些 token 参与 loss”的最终样本语义（`make_batch` 固化到
`TextSampleBatch.flat_loss_mask`），Session 不识别 token/doc/CE。

## 4. 破坏性变更与迁移（v1.10.0 → v1.11.0）

### 4.1 训练 API 层

| 变更 | 旧 → 新 |
|---|---|
| `TrainingSession` 不再持有 `TrainState` | `session.train_state()` / `set_train_state()` **删除**；运行态由 `TextTrainer::train_state()` 持有（`.nnckpt` 保存时与 Session/optimizer 状态合并）。Session 侧只读 `session.state()`（`TrainingSessionState`） |
| 手写 update 管线 | zero_grad → forward/loss/backward → clip → step 的手工接线 → `session.train_step(micro_batch, TrainingStepOptions, step_fn)`（内置累积 + update 边界归一化/裁剪/step/zero_grad）；失败后用 `reset_accumulation()` 丢弃半截 update |
| `TrainingStepOutput` / `TrainingStepOptions` / `TrainingStepReport` | **新增**（Step 回调协议；见 §2） |
| `TrainingConfig` | **新增** `grad_accum_steps`（默认 1）；其余字段不变 |
| `TextTrainer::steps_per_epoch(batch_size)` | → 无参 `steps_per_epoch()`（按 global batch 派生的 **update 数**）；新增 `micro_batch_size()` |
| `TextSampleSet::steps_per_epoch(batch_size)` | 参数语义改为 `steps_per_epoch(global_batch_size)`（返回值 = update 数，不再是 micro 数） |
| `TextSampleSet::valid_target_count(indices)` | **新增**（global-batch 归一化单位预统计） |

### 4.2 Batch 语义与计数口径（同名参数、行为变化——升级时必须核对脚本）

| 变更 | 旧（v1.10.0） → 新（v1.11.0） |
|---|---|
| `--batch-size` / `TextTrainConfig.batch_size` | **micro-batch**（`accum_steps` 把有效 batch 放大为 `batch_size × accum_steps`） → **理论 global batch**（一次 optimizer update 的样本数；micro = `batch_size / accum_steps`，必须整除，否则 `TextTrainer::create` fail-fast） |
| `--accum-steps` | “每 n 步 forward/backward 累加后更新，等效放大 batch” → “一次 update 的 micro-step 数” |
| step 计数 | micro step（每 forward/backward 一步） → **optimizer update**：`steps_per_epoch`、`global_step`、`step_in_epoch`、lr step 调度、`--log-interval` / `--save-interval` / `--max-steps` 全部按 update 计 |
| 等效配置换算 | 旧 `--batch-size 8 --accum-steps 4`（有效 batch 32）→ 新 `--batch-size 32 --accum-steps 4`（micro 8） |

### 4.3 CLI / GUI

- `text_train --help` 的 `--batch-size` / `--accum-steps` / `--save-interval` / `--max-steps` 文案
  随语义更新（`cli/text_train_config.hpp`）；GUI 两个训练页的字段标签同步（`gui.py`）。
- `--resume` 禁列旗标规则、`.nnmodel` warm start 语义均不变。

## 5. 文件与断点兼容

- 模型/断点文件格式仍是 **v8**：外层文件头、参数区、校验和不变。
- 训练状态段新增键 `batch_size_semantics`（`global`/`micro`）与 `micro_batch_size`。
- **v1.10.0 写出的 `.nnckpt` 可继续 `--resume`**：缺语义键按 legacy micro-batch 解释，恢复为
  `global_batch_size = legacy_batch_size × accum_steps`，并把 micro step 计数折算成 update step。
- 旧断点若落在梯度累积中间，pending gradients 原本未落盘，只能从最近 update 边界继续（与 v1.10.0 一致）。
- 反向不完全成立：v1.10.0 二进制读到新状态段会**忽略**新增键，`batch_size` 被按 micro 语义解释
  ⇒ 同一份断点在旧二进制下续训的 batch 语义不同。**回退旧二进制前请保留原文件**。

## 8. 已知限制

- `TrainingStepReport.loss_sum` 的设备侧回读仍是同步语义；异步回读（pending loss）由 Run Driver
  通过 `session.state()` 的 pending 槽自行安排。
- global batch 尾部不满时按剩余样本切 micro-batch，最后一个 micro-step 走 `force_update`；
  该路径的归一化分母仍是本次 update 的实际有效 token 数（理论值动态收紧）。
- `mnist_train` 仍走低层 `zero_grad/clip/step` 原语（无梯度累积需求），迁移 `train_step` 留作后续。
