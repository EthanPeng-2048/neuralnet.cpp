# neuralnet.cpp v1.14.0 Release Notes

> **发布范围**：`v1.13.0`（tag `v1.13.0`，2026-10-26）→ `v1.14.0`（tag `v1.14.0`）。
> **主题**：**训练骨架与开放规格**（RFC 32 阶段 A–D）+ **层与引擎接口补齐**
> （`Embedding`／`CrossAttention`／宿主桥公开 API／推理 batch 作用域）+ **全仓风格基线**。
> **兼容性**：模型/断点文件格式仍为 **v8**，权重与词表段落读写不变；旧断点缺 `state_kind`
> 键一律回退 `TextTrainState`，旧文件数值 `type`（0–7）仍可读。**破坏性变更集中在
> C++ API**（`TrainState` 虚基类化、`ModelSpec` 多态化、复合层默认广播），见 §3 迁移指南。

---

## 1. 主题与定位

v1.14.0 把「训练循环怎么写」从各领域各自实现收进库层的**领域无关骨架**，同时把
**模型规格**开放给第三方自定义类型；并在层/引擎层补齐此前只能靠调用方拼装的三个能力
（可学习查表、交叉注意力、宿主↔设备标量桥）。本版不改 CLI 语义、不改 `.nnmodel`
/ `.nnckpt` / `.nndataset` 的字节布局。

- 设计真源：[`../internal/32-trainer-skeleton-and-openspec.md`](../internal/32-trainer-skeleton-and-openspec.md)、
  [`../internal/30-training-session-step.md`](../internal/30-training-session-step.md)、
  [`../internal/29-session-architecture.md`](../internal/29-session-architecture.md)；
- 调用指南：[`../usage/02-quickstart-train-infer.md`](../usage/02-quickstart-train-infer.md)、
  [`../usage/03-compute-engine-usage.md`](../usage/03-compute-engine-usage.md)。

## 2. 新增能力

### 2.1 领域无关训练骨架（RFC 32 阶段 A–C）

- **`TrainState` 虚基类化**：领域无关字段（计数器 / 配方 / 优化器指针）与编解码骨架
  （`train_state_to_kv` / `train_state_from_kv`）上收为基类；域钩子
  `state_kind()` / `clone()` / `write_extra_kv()` / `read_extra_kv()` / `verify_extra()`。
  文本域派生 `TextTrainState`（`stride` + 数据集身份下沉）。
- **`BatchSource` + `IndexedBatchSource`**（新头 `batch_source.hpp`）：数据供给契约与
  预置索引适配器；shuffle 快照可重放（单流重放同序，`e248b08`）。
- **`RunDriver`**（新头 `run_driver.hpp`）：epoch/步进两种驱动、lr 调度接线、
  `RunHooks{do_update, evaluate, on_epoch_end, on_checkpoint, on_phase}` 领域注入点、
  `RunReport` 统一统计。`global_step` 定义为**绝对步号**（跨续训累计）。
- **`TextTrainer::fit()` 改写为 RunDriver 实例**（dogfood）：CLI 行为与日志口径不变，
  配方 ↔ 会话逐项一致性校验保留。

### 2.2 一站式断点编排（issue #37）

`TrainingSession::save_checkpoint(path, spec, state, tokenizer_data)` 内部同步
`global_step` / `lr` / 优化器 `t` 后以 Checkpoint 角色落盘；
`TrainingSession::resume(path, current, policy)` 一次完成载权重 → 读状态段 →
交叉校验（`ResumePolicy::Strict|Relaxed`）→ 恢复优化器与计数器，返回
`unique_ptr<TrainState>`。调用方不再手工同步两侧计数器。

### 2.3 开放模型规格（issue #26，RFC 32 阶段 D）

- `ModelSpecBase` 携带类型参数与四个分发虚方法
  （`arch_compatible` / `summary` / `write_kv` / `read_kv`）；`ModelSpec` 退化为公共字段外壳
  加 `unique_ptr<ModelSpecBase>`（`clone()` 深拷贝）。
- 五个内建子类：`MlpSpec` / `TransformerSpec` / `GptSpec` / `CnnSpec` / `RaptSpec`；
  原先四处 `switch(type)` 的 `spec_matches` / `spec_summary` / `spec_to_kv` / `spec_from_kv`
  全部收敛为虚方法。
- **`ModelRegistry::register_type("MyNet", factory)`**：自定义类型按字符串类型名注册，
  文件 `type` 键写类型名；内建直通 `make_spec_by_name`。

### 2.4 新层

| 层 | 头文件 | 要点 |
|---|---|---|
| `Embedding` | `compute_layer_embedding.hpp` | 可学习查表；`padding_idx` 行梯度恒零（覆盖写而非累加）；梯度缓冲惰性分配（推理路径不付显存） |
| `CrossAttention` | `compute_layer_attention.hpp` | `AttentionBase` 家族成员，复用 `AttnScoreMask`（`Plain` / `Causal` / `CausalDoc`）；encoder-decoder 交叉注意力，Q 来自解码侧、K/V 来自编码侧 |

两个层都有独立单测（`embedding_test` / `cross_attention_test`，梯度对拍 + 形状/掩码语义）。

### 2.5 引擎与宿主桥

- **宿主桥升公开 API**（issue #30）：`nn::upload_span` / `nn::download_span` /
  `nn::download_vector`（f16 目标自动 cast，`fresh_dst` 语义收口）；`detail::` 包装保留。
- **GPU 单次推理 batch 作用域**（issue #28）：`InferenceScope` RAII + `Model::forward`
  自动作用域；池底材在作用域结束时整块归还，OOM 报错指向根因（不再是模糊的分配失败）。

### 2.6 调度与采样扩展点

- **lr 调度**（issue #31）：新增 `multistep`（milestone × gamma，ImageNet 风格）与
  `step_cosine`（预热 + 分段余弦 + 段末重启，SGDR 风格）；**warmup 对所有 schedule 统一生效**
  （退火进度按扣掉 warmup 的有效区间计算）。
- **`SamplingConfig::logits_transform`**（issue #34）：采样前对 logits 的就地变换钩子
  （`std::function<void(std::span<Scalar>)>`），用于温度外置、禁词、约束解码等定制策略。

### 2.7 复合层默认广播（issue #29）

`Layer` 基类的 `set_training` / `clear_cache` / `set_precision_profile` 默认实现从 no-op
改为按 `param_children()` **逐子层转发**；复合层只列子层即可，漏写转发不再可能让子层
停在 f32 / eval 行为错误 / 显存残留。需特判者仍可 override（先调基类再覆盖）。

### 2.8 子仓与风格基线

- 5 个子仓统一 `v1.<API 变化>.<漏洞修复>` 编号并各自出 tag：
  base `v1.0.2`（sha256 栈缓冲溢出修复 + 格式化）、dataset `v1.0.1`、kvrecord `v1.1.1`
  （格式规范 + Python 参考实现）、threadpool `v1.0.1`、tokenizer `v1.0.1`。
- **全仓（含 5 子仓）按 `.clang-format` 统一格式化**（`5854b98`，约 1.9 万行）；
  此后新增/改动代码走 `git clang-format` 增量，不再有「两种写法共存」的噪声。
- CI：checkout 拉取 submodule、`.gitmodules` 改 HTTPS（拆仓后 CI 双平台构建修复）。

## 3. 破坏性变更与迁移指南

### 3.1 `TrainState` 虚基类化（C++ API）

- 状态段读回改为多态：`peek/load_train_state` 返回 `unique_ptr<TrainState>`，快照走 `clone()`。
- 自定义训练状态需派生 `TrainState` 并实现
  `state_kind()`（落盘键值）/ `clone()` / `write_extra_kv()` / `read_extra_kv()` / `verify_extra()`。
- 迁移：只在 `TextTrainer` / `TrainingSession` 上跑的调用方**无需改动**（`TextTrainState`
  是旧断点的权威类型，缺 `state_kind` 键自动回退）。

### 3.2 `ModelSpec` 多态化（C++ API + 文件 `type` 键含义）

- 文件 `type` 键由数值枚举改为**字符串类型名**；`spec_matches` / `spec_summary` /
  `spec_to_kv` / `spec_from_kv` 四个自由函数被 `ModelSpecBase` 虚方法取代。
- 读侧保留向下兼容：旧文件数值 `type` 0–7 经 `legacy_spec_type_name` 映射
  （4 = ALiBi_GPT 归 `GPT` 同族；6 = ZiPT 仍明确报错）。
- 迁移：直接调上述四个自由函数的代码改调虚方法（`spec.arch->arch_compatible(...)` 等）；
  自定义架构按 §2.3 注册。

### 3.3 复合层默认广播（行为变更）

- 以前「复合层不 override 就不转发」的隐式 no-op 行为**不再存在**：只列 `param_children()`
  即自动广播三开关。若某个复合层**故意**要求子层保持默认（例如三值分流的特判），
  必须显式 override 并在 override 里只对目标子层生效。
- 该变更会让此前被静默忽略的配置错误**显式生效**（这是预期行为，不是回归）。

### 3.4 工具与文档路径

- `bench/doc_align_audit.ps1` 与 `.template/` 图标原件已删除（`62affb8`）；
- 文档目录重构为 `docs/{introduction,development,usage,contributors,internal,history,release-notes,benchmarks}`，
  release note 从仓库根 `release-notes/` 迁入 `docs/release-notes/`——**旧外链失效**；
- `bench/gui_cli_audit.py`、`cli_controllers.py`、`gui.py` 的产物定位改为兼容
  `build/<preset>/`（此前 `cmake --preset` 构建下门禁与 GUI 取不到可执行文件）。

### 3.5 测试目标

- 主仓移除 7 个已下沉到子仓的测试目标（对应能力由子仓各自测试覆盖）。

## 4. 验收基线

> 口径：`NN_ENABLE_NATIVE=OFF` 可移植基线不可用时的本机 `dev` preset 用 `NN_ENABLE_NATIVE=ON`；
> GPU = **NVIDIA CMP 40HX / Vulkan SDK 1.4.350**；构建目录全部从空目录开始（`build/dev`、`build/debug`）。

### 4.1 完整 ctest（Release / Debug）

### 4.2 真实语料端到端训练（40HX）

数据集 = TinyStories 前 20,000 条（`scripts/download_tinystories.py`）→
**20,000 docs / 4,241,421 tokens / 8,208 词表 / 66,273 个 seq64 窗口**（`tokenizer_train` +
`dataset_gen` 生成 `datasets/tiny.nndataset`）。GPT `d_model=64 / heads=4 / layers=2 /
d_ff=128 / seq_len=64`，`--batch-size 8 --accum-steps 2`，**20 update step**：

| 配方 | loss 轨迹（step 5/10/15/20） | 结果 |
|---|---|---|
| f32 | 8.7566 → 8.4056 → 8.0662 → **7.6110** | 1.2 s，无 NaN/冻结 |
| `--f16` | 8.7620 → 8.4353 → 8.0173 → **7.6741** | 0.4 s，无 NaN/冻结 |
| `--t1_58` | 8.9024 → 8.6983 → 8.4716 → **8.1851** | 0.5 s，无 NaN/冻结 |

- **断点续训**：f32 `--save-interval 5` 产出 step20 `.nnckpt` → `--resume` 续 3 步，
  step21–23 loss **7.6525 → 7.5733 → 7.5231**；日志确认优化器状态 76 张量 / `t=20`（adam）恢复。
- **warm start**：f32 `.nnmodel` 续 1 步 loss 7.6361，文件 SHA-256

## 5. 已知限制

1. `--t1_58` 仅 GPT 支持；`--model rapt` 选三值会被配置期拒绝（既有口径）。
2. WSL CPU-only 树中 GPU/offload 用例按 77 skip（无 Vulkan 设备），非源码问题。
3. 四编译器矩阵的 `cl.exe` 一组未在本机复跑（见 §4.3 脚注）。
4. 全仓格式化使 `git blame` 在 `5854b98` 处断代；查历史行归属需
   `git blame -w` 或回看父提交。
5. `TextTrainer` 仍只服务文本/GPT 域；通用 Step 协议由 `RunHooks::do_update` 自行实现
   （本版未抽象出通用 step 接口）。
6. **二次续训的 Adam `t` 退化**（P1）：CLI 续训只恢复优化器状态，不恢复
   `TrainingSession::step_count()`，而 `TextTrainer::make_train_state` 用 `step_count()` 写
   `TrainState.optimizer_step`。因此「续训 → 再存档 → 再续训」链路中的 `t` 会退化为本段步数
   （首次续训不受影响：断点内的 `t` 取自优化器权威值）。修复方向：改用
   `session.optimizer().state_step()`。
7. **`TrainingSession::resume` 错误路径半提交**（P1）：当前先 `load_model` 覆盖权重、后
   `verify_resume`，Strict 校验失败时模型已被改写却返回错误。修复方向：先读取并校验训练状态段，
   通过后再载入权重。
8. 其他 P2：步进驱动在 `steps_per_epoch()==nullopt && max_steps==0` 时空跑并成功返回；
   `save_checkpoint` 用 `optimizer_step` 覆盖 `counters.global_step`（与 RunDriver 的
   `epoch·steps_per_epoch+step` 定义不一致）；`InferenceScope::error()` 在未 `ok()` 时可解引用
   空 optional（现有调用均先判 `ok()`）。
