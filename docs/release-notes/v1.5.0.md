# neuralnet.cpp v1.5.0 Release Notes

> **发布范围**：`v1.4.6`（2026-09-27）→ `ccce40d`（2026-10-01）。
> **提交量**：29 commits，99 files changed，+9188 / −4980；涉及 19 个文档、32 个头文件、42 个 src 文件。
> **主题**：**底层统一收官**（Tensor / ComputeEngine / MemoryPool 的 M1–M6 全部落地）、
> **注意力与位置编码策略化重构**、**BPE 编码性能翻倍**、若干内存/GPU 缺陷修复。
> **兼容性**：本次含**破坏性 API 变更**（见 §7 迁移指南）——`Layer` 四个虚接口签名、`Tensor`
> 访问面、`PrecisionEngine` 删除。库内与仓内所有调用点已同步迁移，外部使用者需按 §7 调整。

## 1. 底层架构统一：Tensor / ComputeEngine / MemoryPool（M1–M6）

设计总纲见 [`docs/development/17-unified-tensor-engine.md`](../development/17-unified-tensor-engine.md)，
前序方案见 [`15-computeengine-refresh.md`](../development/15-computeengine-refresh.md) 与 P0 盘点
[`16-computeengine-p0-inventory.md`](../development/16-computeengine-p0-inventory.md)。

一句话：**契约统一、实现自由** —— 一切 Tensor 的创建、访问、修改只能经由 `ComputeEngine`。

### 1.1 ComputeEngine Refresh P-1：`PrecisionEngine` 装饰器删除

- `include/neuralnet.cpp/compute_precision_engine.hpp`（948 行 / 46 override）**整文件删除**。
- f16 边界 cast 逻辑**下沉为 `ComputeEngine` 基类 NVI**：公有非虚入口承载
  「变体优先 / 全 f32 快速直通 / 抬 f32 → 算 → 按 P 落回」，`protected` 虚 `*_impl` 只管算。
- CPU 33 / GPU 29 处 override 机械改名 `*_impl`；`text_train`/`mnist_train`/`mem_probe`/`f16_*`/`scan_exprs`
  等 7 处使用方迁移，`std::optional<PrecisionEngine>` 舞步删除。
- 精度语义与 `--f16` 等 CLI 行为不变（`profile_f16()` 仍是 `{param:F16, compute:F16, stable:F32, optimizer:F32}`），
  仅注释口径从"CLI 决定是否启用适配层"改为"边界 cast 入口常驻基类"。

### 1.2 Refresh P1：张量出生绑定 + 跨引擎检查

- `Tensor` 新增 8B `observer_ptr<ComputeEngine> engine_` 与 `bound()`/`engine()`；拷贝 / `reshape` 传播绑定。
- 引擎公共入口统一 `stamp_`：**库内产物出生即绑定**；`dsl::compute`/`compute_reduce` 出口走内部 `adopt` 通道。
- `bind_check_` 跨引擎检查：**双方都绑定且指针不同 → 硬错误**；单侧未绑定放行。
  `NN_BIND_DEBUG=1` 时未绑定输入也报错（带 `source_location` + 张量形状），用于抓库内漏网。

### 1.3 M1：Tensor 访问收口（铁律 #11）

- `Tensor` 的静态直构工厂（`from_matrix`/`cpu`/`cpu_uninitialized`/`from_gpu`…）、存储构造、访问器
  （`cpu_matrix`/`cpu_shared`/`gpu_tensor`/`gpu_shared`）、`reshape` **全部转 private**。
  friend 集仅 `ComputeEngine`/`CpuEngine`/`GpuEngine` + `detail::TensorAccess`（DSL 求值器专用，库外禁用）。
- **绕过引擎 = 编译错误**。公共面收敛为形状/精度/设备查询、`bound()/engine()`、`valid()`、`shape_str()`。
- `ComputeEngine::reshape` 落地（D10）：元素数不匹配返回 `Result` 错误（原 `NN_ASSERT` 升级）。
- 库外（9 个测试文件 + `text_train` + `scan_exprs`）全部迁 `engine.create_tensor/from_matrix/to_matrix`，
  不留过渡期；`test_common.hpp` 新增 `upload/download` 助手。

### 1.4 M2：声明式初始化（`InitSpec`）

- `InitSpec{Uninitialized, Zero, Constant, Uniform, Normal}` + 四参
  `engine.create_tensor(rows, cols, P, spec)`；**层算分布参数、引擎填数**（策略调用方不可见）。
- 分布类 **seed 必填**（层传 `kInitSeed = 42`）；引擎内按创建序号 `splitmix64` 混流，
  同形状多层不再互为镜像。
- `Layer::init` 全量迁移（Linear/Conv2D/LayerNorm/RMSNorm/token_emb/可学习位置编码/CrossAttention P/ones_row_），
  `mlp`/`conv` 的 `thread_local rng_` 与 init 侧 `random_device` 清零 → **初值跨进程逐字节确定**。
- 新增探针模式 `gpu_stability_probe --init-hash`：6 类模型建后即哈希，供跨进程 diff。

### 1.5 M3：批量读写 API

- I/O 分组六动词成文：`from_matrix`/`to_matrix`/`read`/`write`/`get_index`/`set_index`（保留原名，D9）。
- **批量 `read/write` 是本体**：span 元素类型与 `t.precision()` **精确匹配**
  （`float`↔F32、`f16`↔F16，错配运行期错误、类型非法编译期 `static_assert`）；
  GPU `read` 隐含 flush + 同步，`write` 覆盖既有存储不替换对象。
- **索引级是语法糖**：宿主直读写；GPU 每次一整轮 staging，不承诺热循环性能。
- 新增 `gpu_stability_probe --io-roundtrip`：三用例（f32 往返 / f16 RHE 往返 / 录制窗口批量写读）。

### 1.6 M4：Matrix 降级为宿主 I/O 载体（铁律 #12）

- **L2+（Layer/Loss/Optimizer/Model）头文件零 `Matrix`、零 `from_matrix/to_matrix/copy_from`**。
- 层自算辅助数据（RoPE cos/sin、正弦位置编码、ALiBi 斜率、文档掩码、索引、卷积置换、patch 提取…）
  全部迁 **span 宿主桥** `detail::upload_span/download_span/download_vector`（内部 = M3 批量 `write/read`）
  或 `create_tensor` + `InitSpec`/`zero`：共 **45 处 I/O + 32 处类型**。
- 新增审计：`bench/doc_inventory.ps1` 第 [4] 节，验收口径 `L2-VIOLATIONS: 0`（宿主桥用量只披露）。
- **数值零变化**：迁移属纯载体替换，CPU/GPU 字节锚与迁移前逐位一致。

### 1.7 M5：内存池契约统一

- 新增 `nn::HostAllocLedger`（`algebra_matrix.hpp`，relaxed 原子）记账宿主直配；`MatrixT` 的
  **析构 / 移动赋值 / `resize()` 三处释放出口**统一走 `release_storage_()`。
- `ComputeEngine::pool_stats()` **不再有"CPU 返回空串"的空档**：无池引擎返回
  `direct{ blocks=… live_bytes=… peak_bytes=… total_blocks=… total_bytes=… }`；GPU 照旧 `persist{…} transient{…}`。
- `release_idle_pool_blocks()` 对 CPU 是**语义成立的 no-op**（已写入头注释与
  [`04-memory-optimization.md`](../development/04-memory-optimization.md)）。
- 训练日志现在**一套代码读两个引擎**。

### 1.8 M6：段 A / 段 B / 段 C 三段全落地

**段 A（D6/D7/D8 + 门禁）**

- **D6-1 真缺陷修复**：`load_model` v5 两支都白做上传与 PCIe 往返 → 收敛为 `engine.copy_from(p_tensor, file_matrix)`
  一行。实证：`--save A` → `--resume A --lr 0 --save B`，**A/B SHA256 完全相同**。
- **D6-3**：`matmul_with_bias_impl` 的宿主兜底默认实现改为 `= 0;` **纯虚** —— 删死码，
  未来第三后端必须给出真现值，不可能静默退化成主机往返。
- **D7**：删除死码 `Model::set_engine`（绑定只经 `Model(ComputeEngine&)`）。
- **D8**：基类 offload 占位改 `create_tensor`。
- **`NN_BIND_DEBUG=1 ctest` 打通为可执行门禁**（修两处库内中转漏网 + `bind_error_` 同步打 stderr）。

**段 B（`ensure_gpu` → `import`）**

- 新增引擎契约 `ComputeEngine::import(src[, P])`（公共 NVI + 新虚 `import_impl`，
  **virtual 方法 48 → 49**）：同设备同精度零拷贝别名 / 同设备异精度引擎内 cast / 跨设备经宿主中转。
- **16 §2 的 43 处 `ensure_gpu` 调用点全部改名 `import`**，符号 `ensure_gpu` 清零（命名即防线）。
- `import` **返回新句柄、不改写 `src`**；顺带修掉原实现硬取 `cpu_matrix()`（F32 槽）对 f16 源取空指针的隐患。

**段 C（删 `Layer` 每调用 engine 形参）**

- `Layer` 新增 `ComputeEngine* engine_`；`init` 改 **NVI**（公共 `init(engine)` 绑定后转 `init_impl`，
  17 处层 override 改名）。
- 四个虚接口去形参；方法体首行局部 `ComputeEngine& engine = engine_ref();`（54 处），方法体零改写。
- **新不变量：复合层 `init_impl` 必须 init 全部子层**（含 ReLU/GeLU/SwiGLU/Softmax/`pos_encoding_` 等无参量子层），
  漏了会 fail-fast 并打印调用点 `file:line`（`std::source_location` 诊断保留为长期工具）。
- 库外配合：`scan_exprs` 的 9 处「构造后直接 forward」补 `init(engine)`；测试 6 处同理。
- **保留 engine 形参**（有意为之，见 §7）：`Loss::forward/forward_sparse`、DSL 入口、
  `PositionEncoder`/`RotaryEmbedding` 等辅助对象与层内私有 helper。

## 2. 注意力与位置编码策略化重构

这是本轮**结构改动最大**的一块：从"一个类里塞多种注意力 + 布尔标志位 + 虚钩子"改为
**两个正交策略对象、构造期定型**。

### 2.1 掩码策略族 `AttnScoreMask`

- 从 `AttentionBase` 的 `use_rope_` 布尔 + `use_alibi_`/`has_doc_ids_` 布尔 + `fold_mask_variant_()` 虚钩子
  + 4 个 `masked_*_` 模板，改为 **每种掩码语义一个类**：
  `PlainScoreMask` / `CausalScoreMask` / `CausalDocScoreMask`，只做掩码。
- 由 `AttentionBase::make_score_mask_()` 在**配置期**（构造 / `set_doc_ids`）工厂化选定；
  forward/backward 各只做**一次虚调用**，热路径里没有变体判断。
- `expr::FoldAttnMask`（5 值融合枚举）拆为 `expr::AttnMaskKind{Plain, Causal, CausalDoc}` **× `bool score_bias`**；
  `scan_exprs` 登记块改为 3×2 组合循环（跳过不存在的 "Plain + 偏置"），掩码策略类 5 → 3。
- **位置偏置被摘出掩码族**：ALiBi 由 `PositionEncoder::apply_score_bias()` 在
  "掩码之后、softmax 之前"独立叠加（非 ALiBi = no-op），forward 仍融在同一个 fold kernel 内。

### 2.2 位置编码策略族 `PositionEncoder`（新文件 `compute_position_encoding.hpp`，651 行）

- `PositionEncoder` 基类按**注入点**分三组，各子类只覆写自己那组、其余继承 no-op：

  | 策略 | 注入点 | 实现 |
  |---|---|---|
  | `Learned` / `Sinusoidal` | 嵌入侧（`apply`/`apply_step`/`backward`） | 加性融合 |
  | `RoPE` | Q/K 侧（`apply_qk`/`apply_qk_step`/`set_position_offset`） | 旋转；持有 `RotaryEmbedding`（cos/sin 表） |
  | `ALiBi` | 分数侧（`has_score_bias`/`prepare_score_bias`/`apply_score_bias`） | 线性距离偏置 |
  | `NoPositionEncoder` | — | 恒等 |

- **所有权按注入点划分（谁拥有 = 谁负责）**，`PosEncodingType` 分发只剩两个工厂：
  - 模型侧 `make_embedding_position_encoder(type, d_model, seq_len)`，由 `GPTModel`/`RAPTModel` 持有；
  - 注意力侧 `make_attention_position_encoder(type, d_k, num_heads)`，由 `CausalSelfAttention`/`ReLULinearAttention` **自持**。
- **删除层间对象传递**：`AttentionBase::set_position_encoder`、`GPTBlock::set_position_encoder`、
  `RAPTBlock::set_position_encoder` 与两个模型的注入循环全部移除，同时去掉了
  "非拥有指针指向模型对象"的生命周期约束。
- 代价：**RoPE 的 cos/sin 表随层构建**（默认配置 ≈64KB/层、全模型 256KB，仅 `seq` 变化时重算）。
- `RotaryEmbedding` 从 attention 头迁出，`use_rope_` 布尔消失。

> ⚠ **踩坑记录（已写入 AGENTS §7 告警）**：把 ALiBi 偏置从掩码表达式拆成**独立一步**后，
> 新 spec 里没有 matmul → `MatmulSpec.batch` 退化为 1 → `dsl::row()` 从"批内行号"变为"全局行号"
> → 偏置**静默错值**（实测 |偏置| 达 27，理论界 ≈7）。
> 修法：改用 `(rows,1)` 行表 + `dsl::row_broadcast`（按全局行号直读，与网格分解无关）。

## 3. 分词器（Tokenizer）性能

### 3.1 保序并行 `encode`

- `encode` 改为 `encode_segments_`：按**空白串起点**分段 → 全局线程池并发编码 → **按段下标升序拼接**。
- 正确性依据（已作为契约写入代码注释）：安全切分点对 BPE/CharBPE 的预分词**必然是 chunk 边界**；
  标记不含空白故不会被切断；预分词与合并都是 chunk 局部操作 → **任意并行度与顺序执行逐字节一致**（铁律 #8）。
- 文本 < 256 KiB（`PARALLEL_ENCODE_MIN_BYTES`）或找不到切分点时回退顺序路径。
- 新增 `Tokenizer::set_encode_threads(0=自动 / 1=顺序 / >1=指定)`。
- **实测 8 MiB 多样文本 `encode` 0.93s → 0.134s（32 线程，7.0×）**。

### 3.2 每 chunk 零堆分配

- `bpe_merge_impl_` 改为 thread_local `BpeMergeScratch` 复用容量、结果追加到调用方 `out`、
  堆用 `std::push_heap/pop_heap` 手工维护（与 `std::priority_queue` 同算法，**弹出顺序逐位相同**）。
- **实测 34MB 语料 `tokenizer_infer --encode-file` 单线程 18.4s → 9.2s**。
- 输出逐字节不变：`.tokcache` 重新生成 SHA256 与旧实现完全一致。

### 3.3 CLI / 入口

- `tokenizer_infer` 新增 `--threads <n>`。
- `text_train::parallel_tokenize` 从 `std::async` 每块一个 future 改为
  **按块下标写 `parts[c]` + `nn::parallel_for_samples`**，块边界不变，token 流与 doc_ids 逐字节不变。

## 4. 缺陷修复与安全加固

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 4.1 | **CNN 在 GPU 上硬报错 `validate_expr_spec: empty instruction list`**（同规格 CPU 正常、ctest 全绿） | `dsl::compute` 的**根节点是裸视图**（`grouped_reduce_max`/`row_broadcast` 等只登记 view/input 不产生指令）→ 指令表为空；而 CPU 编译期模板路径**根本不校验** | MaxPool2D 前反向的根视图与**运行时 0** 相加（`+ dsl::rparam(Scalar{0})`，不进 key、语义不变）；扫描模式下 `validate_expr_spec` 失败即 `std::_Exit(3)` **硬失败**（把 GPU 运行期错误前移到构建期）；`scan_exprs` 的 Conv/MaxPool dry-run 改为显式检查返回值；**ctest 新增 `cnn_test_gpu`**（无 Vulkan 返回 77 = SKIP） |
| 4.2 | **v5 模型文件形状是未信任输入** | `rows`/`cols` 直接来自文件：巨量形状 → `bad_alloc` 在 `-fno-exceptions` 下 terminate；乘法溢出回绕 → 小缓冲 + 巨大元数据 → 越界读写 | 分配前用**除法比较**（全程无乘法溢出）校验矩阵字节数 ≤ 文件剩余字节；`model_spec_validation_test` 新增三用例（2^40×2^40 拒绝 / 数据不足拒绝 / 正常 2×3 放行） |
| 4.3 | **GPU 稳定性探针首个 `vkCreateBuffer` 即崩**（16 §7-2 遗留未决项） | `GpuBackend::instance()` 只是惰性单例，Vulkan 设备须显式 `backend.initialize()`；探针漏调 | 探针建引擎前补 `initialize()`；修复后 Windows 本机 **dev0/dev2/dev4 进程内两轮 + 跨进程两次启动 loss 与 hash 逐字节一致** |
| 4.4 | **`ThreadPool` 析构期死锁** | 置 `stop_` 未持 `queue_mutex_` 就 `notify` → worker 可能刚判完谓词、尚未进入 `wait()`，本次唤醒丢失 → worker 永久睡眠 → `join` 永久阻塞 | 与 `finish_chunk` 统一丢唤醒规则：持 `queue_mutex_` 再 `notify_all` |
| 4.5 | `load_model` 每参数白做一次全量上传 / 两个多余 PCIe 往返 | v5 同精度支上传后丢弃结果再 `copy_from`；跨精度支多两次往返 | 收敛为 `copy_from` 一行；`save→load→save` SHA256 逐字节一致（f32 与 f16-param 两模型） |
| 4.6 | `matmul_with_bias_impl` 默认体是宿主 PCIe 兜底 | 两个子类均已 override，默认体是死码 | 改 `= 0;` **纯虚**（编译期强制真现值） |
| 4.7 | `ensure_gpu` 对 f16 源硬取 `cpu_matrix()`（F32 槽）→ 空指针隐患 | 隐式上传路径假定源为 f32 | `import_impl` 的 f16 源改走宿主中转分支 |
| 4.8 | 构建工具失败路径用 `std::abort()` → ninja 挂死到超时 | SIGABRT handler 做 stacktrace 分配，线程池 worker 存活时卡死 | 构建步骤失败路径一律 `std::_Exit(非零码)`（不碰信号处理器/堆） |

## 5. Layer 层收敛与错误传播

- **`NN_TRY(decl, expr)` / `NN_TRY_CHECK(x)`**（`core_errors.hpp`）：L2 层 494 处
  `auto r = f(); if (!r) return std::unexpected(r.error());` 收敛。展开与手写形态**逐字等价**
  （错误消息、返回类型、语句数），不含控制流/所有权语义；用普通语句而非 `do{}while(0)`，
  保持 `if/else` 悬垂-else 行为一致。配套脚本 `tools/apply_nn_try.ps1`（带 `-DryRun` 计数）。
- **参数收集**：15 处同构的 `p.insert(p.end(), x.begin(), x.end())` 级联 →
  `Layer::collect_refs(...)` / `Layer::collect_block_refs_()`。拼接顺序即实参顺序，优化器看到的参数序不变。
- **Pre-Norm 残差**：`GPTBlock`/`TransformerEncoderLayer`/`RAPTBlock` 的两处正/反向分流 →
  `Layer::prenorm_residual_forward_/backward_`。**残差相加的表达式输出精度显式传入**
  （GPT/Transformer = `p.compute`，RAPT = `F32` 保持历史行为，不"顺手统一"以免改变 f16 数值）。
- **解码采样**：`GPTModel`/`RAPTModel::generate()` 的三段（temperature → 数值稳定 softmax
  → 采样/贪心）→ `sample_next_token_()`；RNG 消耗序保持不变。
  **解码循环骨架刻意未合并**（两者运行态本质不同：KV cache 增量 / RLA 运行态）。

## 7. 破坏性变更与迁移指南

### 7.1 `Layer` 四个虚接口不再收 `engine` 形参 ⚠ 影响最大

```cpp
// 旧
auto y = layer.forward(engine, x);
auto g = layer.backward(engine, grad);
layer.zero_grad(engine);
auto y = layer.forward_recompute(engine, saved);

// 新
auto r = layer.init(engine);          // 必须先绑定（Model::add 会自动调）
auto y = layer.forward(x);
auto g = layer.backward(grad);
layer.zero_grad();
auto y = layer.forward_recompute(saved);
```

- **手工构造的层必须先 `layer.init(engine)`**；未绑定即 fail-fast 并打印调用点 `file:line`。
- 自定义层覆写 `init(...)` 需改名 **`init_impl(...)`**（`init` 已是 NVI）。
- **复合层 `init_impl` 必须 init 全部子层**，包括 ReLU/GeLU/SwiGLU/Softmax 等无参量子层与
  `pos_encoding_`——它们以前靠 forward 形参拿引擎。
- **仍然收 engine 形参**：`Loss::forward/forward_sparse`、`engine.from_matrix`、
  `dsl::compute*` 入口、`PositionEncoder`/`RotaryEmbedding` 的 `apply/backward`、
  `ActivationOffloader`、层内私有 helper。

### 7.2 `Tensor` 访问面私有化

- `Tensor::from_matrix/cpu/cpu_uninitialized/from_gpu`、`cpu_matrix()/cpu_shared()/gpu_tensor()/gpu_shared()`、
  `reshape()` **全部私有**。请改用 `engine.create_tensor` / `from_matrix` / `to_matrix` /
  `read` / `write` / `get_index` / `set_index` / `reshape` / `cast` / `import`。
- `detail::TensorAccess` 为 DSL 求值器专用通道，**库外禁用**（违反靠 `doc_inventory.ps1` 审计抓）。

### 7.3 `PrecisionEngine` 删除

- 删掉 `#include <neuralnet.cpp/compute_precision_engine.hpp>`；直接用 `CpuEngine`/`GpuEngine`/`ComputeEngine`。
- 非 f32 profile 由基类 NVI 入口自动接管，全 f32 时零开销直通。

### 7.4 移除：AttnZip / ZiPT ⚠

- **`ZiPTModel` / `ZiPTBlock` / `CrossAttention` 整体移除**（连同 `build_zipt_model*`、
  `make_zipt_spec`、`ZiPTConfig`、`ZIPT_MEMORY_TOKENS`、`ModelSpec::is_zipt()` 与
  `memory_tokens`/`window` 字段、`--model zipt` / `--window` / `--memory-tokens`、`zipt_test`）。
  代码完整保留在 **`legacy/zipt` 分支**。
- **恢复前提**（两条同时满足）：① 算法层——压缩向量必须因果；② 代码层——实现质量对齐
  RAPT/GPT（梯度检查点 + activation offload + CLI/序列化/测试齐备），且有同参同预算的对比数据。
  裁决依据见 [`docs/history.md`](../history.md)「ZiPT 移除」条与 `AGENTS.md` §12。
- 旧模型文件：`ModelType` 的 6 号取值保留为 `Reserved_ZiPT` 占位，加载 `type=6` 的 `.bin`
  会得到**明确错误**（而非静默 `Unknown`）。

### 7.5 其他

- `Model::set_engine` **已删除**；绑定只经 `Model(ComputeEngine&)`。
- 引擎内部 `ensure_gpu` → **`import`**（返回新句柄、**不改写 `src`**）。
- 第三方 `ComputeEngine` 子类必须实现 `matmul_with_bias_impl`（已纯虚）与 `import_impl`。
- 位置编码：`RotaryEmbedding` 移到 `compute_position_encoding.hpp`；
  `AttentionBase::set_position_encoder` / `GPTBlock::set_position_encoder` /
  `RAPTBlock::set_position_encoder` **已删除**（改为层自持）。
- IR：`expr::FoldAttnMask` 5 值枚举 → `expr::AttnMaskKind`（3）+ `bool score_bias`。
- 新增契约 `Layer::init_impl`、`Tokenizer::set_encode_threads`、`tokenizer_infer --threads`。

## 8. 已知问题（本次未修）

- **GPU `stable=f16` 训练 loss 打印冻结（未修）**：`text_train --precision-stable f16` 时 step 恒 4.0137、
  跨 epoch/跨进程逐位相同；**权重照常更新**（冻结仅在 loss 回读链）；CPU 同配置健康；
  ctest 20/20 全绿但**无 GPU + stable=f16 用例**。
  触发矩阵与证据见 [`14-f16-stable-gpu-loss-frozen.md`](../development/14-f16-stable-gpu-loss-frozen.md)。
  **推荐路径 `--f16`（stable/optimizer=f32）实测健康。**
- **数值性限制**：四字段全 f16 不可训练——`optimizer=f16` 单独即令 Adam 更新爆炸，
  `stable=f16` 链约 200 步 NaN（见 [`05-mixed-precision.md`](../development/05-mixed-precision.md) §12.5）。
- **`text_train --model zipt` 启动即中止（未修）** → **已随 ZiPT 整体移除而消失**：
  AttnZip/ZiPT 已从主线移除（现直接报"未知模型架构"），代码保留在 `legacy/zipt` 分支；
  恢复前提见 §7.4 与 [`docs/history.md`](../history.md)。
- **不存在的 CLI 参数**：`--tdr-retry` / `--max-tdr-retries`（请勿引用）。
- **`text_train` 跨进程不可复现**：数据洗牌 RNG 仍为 `mt19937_64{random_device{}()}`
  （M2 裁定属运行期随机性、不迁 InitSpec）；要全链路复现需另立「数据洗牌种子」类开关（**当前尚无此 CLI 参数**）。
- **GPU dev1（MESA/D3D12 转译）不可用**：初始化即报 DXIL container 校验错误、exit=2（设备级问题，非库问题）。
