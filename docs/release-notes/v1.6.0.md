> **发布范围**：`v1.5.1`（586cfb2，2026-10-01）→ `v1.6.0`；内容提交截至 `f093261`（2026-10-02），其后仅含本发布文档与版本同步提交。

## 1. key 契约：key 只描述结构

- **步骤①**（`3cf591c`）常量池**值**退出 key → 值走 push constant `c<i>`。
- **步骤②**（`b960450`）`MatmulSpec.transA/transB` 退出 key → `mm_trans` push constant（shader 内两条加载路径 + uniform 分支）。
- **步骤③**（`148d1d7`）分组归约 **R** 退出 key → 视图参数 `vp`（`gr_r<i>()` 运行期循环），同一结构不同 R 共享一个 shader。
- **精度签名退出 key**（见 §3）：旧 `key#<sighex>` 形式消失。
- **属于结构、仍必须进 key**：`AttnScoreMask::mask_kind()`、`FoldSpec.tri_skip`。
- **契约回归测试**：`src/expr_fused_key_test.cpp`（`0c68197`，并入 `expr_cpu_test`）把“结构 = 表达式类型”锁进 ctest——谁把运行期值塞回 key，测试就地红。

收益：注册表体积与闭合世界键空间不再随常量/形状/精度组合膨胀，miss 面只取决于“真正产生代码分歧”的维度。

## 2. 锚点自登记与收集三路

- `dsl::compute` 系列表达式在**静态初始化期**按表达式类型自登记（`FusedAnchor<Expr>`，步骤⑤ `41b4374`，前置修复 `31051a3`）——编译期可达，dry-run 跑不到的分支也覆盖。
- **实测分工（84 条结构）**：per-layer dry-run 38（含模型 pass +25、显式登记 +8）、锚点 59，重叠 46 → 锚点独有 13、dry-run 独有 25。**任何一方单独删掉都会丢结构。**
- **模型 pass**（`63b7d72`/`03f9383`/`484ae35`）补齐“运行期配置决定”的变体（视图种类/项数在类型层面推不出）；失败从 warning 升级为**构建失败**（`14892f5` 缺陷 7）。
- 删除 13 个已被模型 pass 覆盖的 per-layer dry-run 块（−223 行，`98f887a`）。
- **来源诊断**：`NN_SCAN_DUMP_SOURCES=1` 逐条打印结构来源，含指令序列（`7c3af60`/`bf8d10e`）。
- **闭合世界报错带 `key=`**（`9300bf8`）：报错可直接定位注册表条目。

## 3. 运行期精度分派 V1：签名从“身份”降级为“参数”

- emitter 新增 V1 发射模式（`aba9ecb`）：每个输入/输出声明 f32 + `float16_t` **双视图**，加载/存储按 push constant `uint prec`（bit i = 输入 i 为 f16，bit16 = 输出 f16）走分支 → **一份 shader 覆盖任意签名**（`2b43846`）。
- 构建期每个结构发**三份**：V0 全 f32（键 `key`）/ V1 运行期分派（键 `key#x`）/ V2 native16（键 `key#a`，按 `expr_prec_sig_native16` 结构谓词判定）。
- **运行期三档**：`key#a` → `key#x` → 基类边界 cast。`#x` 生成被跳过 / `NN_SCAN_NO_DISPATCH=1` / 设备无 16bit 存储时落 cast，`[prec][miss]` 仍会触发（通用诊断，**不是错误**）。
- **删除的旧机制**：签名回填清单 `tools/prec_backfill.txt` 与回填流程（`6c9e091`）、f16 第二遍扫描（实测结构贡献恒 0 → **扫描工作量减半**）、注册表 variants 残留机制与死分支（`f334cd2`）。
- **V2 谓词重跑**（`14892f5` 缺陷 1）：谓词含常量值判据（0<|c|<6e-8 在 f16 下 flush-to-0）而常量值不进 key → 选 `#a` 前必须用**真实实例的 spec** 重跑同一谓词，否则同结构换常量会被套上 flush 的 native16 shader（静默错值）。
- **`NN_PREC_TRACE` 盲区修复**（`17381ab`）：先打后查 + 查询入口双打点导致计数翻倍（12040 行 = 6020×2）→ 确认命中后才打、只由真正 dispatch 的入口打。实测 **6022 行 / 24 条 distinct 结构 = 20 `#x` + 4 `#a`**，覆盖四个生成器族（元素 9 / 归约 6 / matmul 4 / fold 1），miss 0。

## 4. 构建管线单步化 + 库外融合能力

- **单步 scan_exprs**（`0bdaa97`）：独立工具 `gen_fused` 改为头文件 `tools/fused_generate.hpp`、并入 `scan_exprs`（收集 + 生成同进程），`.cpp` 入口已删除；同时删除 `write_registry/read_registry` 与 `.bin` 中间序列化。
- **`nn_enable_gpu_fusion(<target> MAIN <src>)`**（`476e057`，定义在本仓 `CMakeLists.txt` 的 `if(Vulkan_FOUND)` 内）：收集器 = **库内收集逻辑**（锚点 + dry-run + 模型 pass + 显式登记）**加上本目标全部 TU**（`-DNN_EXPR_SCAN` 编译，调用点自登记），并继承目标的 `INCLUDE_DIRECTORIES` / `COMPILE_DEFINITIONS` / `COMPILE_OPTIONS`（生成器表达式）。⚠ 库内收集逻辑不能省——84 条里只有 13 条来自编译期锚点。
- **include 顺序**（`a2c90fb`）：`${NNF_OUT_DIR}` 以 **BEFORE** 插到库 `${CMAKE_BINARY_DIR}/generated` 之前（普通 append 对重复项保留首次出现位置，会排反）；否则 `__has_include("fused_registry.hpp")` 解析到库那份、使用者结构全部闭合世界报错。
- **多 TU header-only 链接修复**：类外定义漏 `inline` → duplicate symbol（样例抓到）。
- **端到端验收**（`examples/fusion_custom_layer*`，两种自研算子形态，均只用锚点）：
  - 逐元素 `exp(|x|·α)/(√|y|+α)`：CPU f32 `0.6712035`（差 0）/ GPU f32（V0）`0.6712036`（差 5.96e-08）/ GPU **f16（V1 运行期分派）** `0.6708984`（差 3.05e-04，f16 舍入内）。
  - 归一化形态 `rsqrt(col_reduce_sum(x)·inv + ε)`（`raxis=1`、`viewkinds=[0,8]`，与库内 LayerNorm/RMSNorm 同形）：GPU f16 `1.2246094`。
  - 含 rparams ⇒ native16 谓词不通过 ⇒ f16 命中必然是 `key#x`；注册表漏条目即硬报错，“跑通”本身即断言。
- **残余不确定性**：25 条结构只有执行 Layer/模型才拿得到（锚点符号实例 `Expr{}` 与运行期实例折叠结果不同）；实测两种形态不在其中但无法先验排除。若下游遇到闭合世界报错，预案是给 `nn_enable_gpu_fusion` 加 `COLLECT <file>` 钩子（触发条件见 [`18-roadmap.md`](../development/18-roadmap.md)）。

## 6. 缺陷修复

### 6.1 审核修 9 处真缺陷（`14892f5`）

对 `feat/fused-runtime-prec-dispatch` 全量改动做简化/规范化/指针与内存/逻辑审核，修掉：

1. **native16 谓词与 key 错配（静默错值）**：生成期用“生成那一份时的常量”判定、运行期按位图选 `#a` → 同结构换常量即被套上会 flush 的 shader；改为选 `#a` 前用真实实例 spec 重跑谓词。
2. `[prec][hit]` 先打后查 + 查询入口也打 → 计数翻倍（12040 = 6020×2）→ 确认命中后才打。
3. push constant 固定头长度创建侧/写入侧各推一遍 → 注册时算一次存 map，写入侧只读。
4. f16 视图名用**子串替换**拼：找不到前缀时静默保留 f32 视图名 → 把 2B 缓冲当 `float` 读；改为显式拼名。
5. `nn_enable_gpu_fusion` 的 include 顺序不成立（append 保留首次位置）→ 改 `BEFORE`。
6. 收集器不继承目标编译条件（`NN_HAS_VULKAN` / 私有 include / 自定义宏）⇒ 使用者调用点静默消失；改为生成器表达式继承，`MAIN` 未匹配即 `FATAL_ERROR`。
7. 模型 pass 失败只 warning（它贡献 25/84 条结构）→ 改为**失败即构建失败**。
8. **两条永远通过的测试**：fold `tri_skip` 断言比较的是 body 本就不同的两个枚举；重复的 `mm_trans` 位编码断言删掉一份。
9. `read_spv` 不校验 `tellg()`（失败返回 −1 → `size_t(-1)/4` 请求 ~4GB）+ 忽略截断读。

同批删除死物（`prec_manifest` 形参、`ExprRegistry::contains`、`fusion_anchor_touch`、`std::exit(1)`、重复 4 次的 matmul trans 登记）并消掉 4 类“同一份知识写在两处”的同步点。**教训**：9 条真缺陷里 4 条同形——谓词 vs key、创建侧 vs 写入侧 PC 长度、f16 视图名 vs 子串替换、目标编译条件 vs 收集器；另两条是“测量/断言必须先证明它能失败”的延续。

### 6.2 干净构建三缺陷（`f093261`）

首次把仓库放进**注册表缺失的干净构建目录**编译即暴露——此前开发机 `build/generated/fused_registry.hpp` 长期常驻、所有验收都在脏构建目录上进行：

1. `compute_vk_backend.hpp` 直接使用 `expr_spec.hpp` 的 6 个符号（`ExprPrecSig`/`EXPR_PREC_DISPATCH_SUFFIX`/`EXPR_MAX_INPUTS`/`EXPR_MAX_CONSTS`/`EXPR_MATMUL_BLOCK`/`EXPR_FOLD_ROWS_PER_WG`），却只靠生成的 `fused_registry.hpp` 传递带入 → 注册表缺失时 **clang 与 MSVC 在完全相同的符号列表上报错**（证明非 MSVC 特有）→ 显式 include。
2. 收集器继承了目标的 `INCLUDE_DIRECTORIES`（含其自身产物目录）→ 注册表存在时 depfile 记录 `fused_registry.hpp → collect.exe → .obj → fused_registry.hpp` = **ninja 依赖环**，图加载失败 → 立不变量 **`NN_EXPR_SCAN ⇒ 不嵌入 fused_registry`**（收集器是生成者，绝不消费自己的产物）。
3. `compute_gpu_engine.hpp` 的 `psig` 声明在 `#ifdef NN_FUSED_REGISTRY_EMBEDDED` 内、使用在无 ifdef 的 1509 行 + 连带 unused-parameter `-Werror` → `psig` 无条件计算（无注册表时 NVI 已抬 f32 → 恒 0 → 正确落闭合世界错误），`rows/cols` 加 `#ifndef` 消警。

**语义零变化**：结构数、精度变体、ctest、样例值全部不变——修复只影响“注册表不存在时能否编译”。

## 7. 契约变更与迁移指南

### 7.1 注册表 key 形式（影响读 key 的工具/脚本）

- 旧 `key#<sighex>` / `key#<sighex>#a` 形式**消失**，现在只有 `key`、`key#x`、`key#a`。
- 下游若解析 `fused_registry.hpp` 的键、或依赖 `NN_PREC_TRACE` 输出里的签名 hex → 按三档命名更新；`tools/decode_fused.py` 按条目透传 key，不受影响（只是打印的 key 形式变了）。

### 7.2 构建工具链

- 独立工具 `gen_fused` **已删除**，并入 `scan_exprs`（单步）；调用 `gen_fused` 的脚本改为直接重跑构建（`scan_exprs` 由 CMake 编排）。
- 签名回填工作流（`tools/prec_backfill.txt`、`NN_PREC_TRACE` 的“补变体”流程）**已失效**——V1 一份 shader 覆盖任意签名，不再需要回填；`NN_PREC_TRACE` 现在是变体选择事件日志。
- `NN_SCAN_NO_DISPATCH=1`（跳过 `#x` 发射）与 `NN_SCAN_NO_DRYRUN=1`（同时门控模型 pass）逃生阀保留。
- IR-D emitter 抽象（`expr_emitter.hpp`，`--list-backends`）不受影响，目前仅 `glsl` 后端注册。

### 7.3 新增（加性）

- CMake `nn_enable_gpu_fusion(<target> MAIN <src>)`（注意：函数在本仓 `CMakeLists.txt` 内、仓库无 `install()`/export，真正树外工程复用需先做 install/export，见 [`18-roadmap.md`](../development/18-roadmap.md) E2）。样例 `examples/fusion_custom_layer*`。
- 新契约测试、`fusion_custom_layer_example` ctest、`NN_SCAN_DUMP_SOURCES` 来源诊断、闭合世界报错带 `key=`。

### 7.4 无破坏

- `ComputeEngine` virtual 方法数 **49 不变**；Layer / Tensor / 序列化 / CLI 无签名变更；与 v1.5.0 不同，本次**没有** L2 层面的迁移工作量。
- `CMakeLists.txt` 的 `project(... VERSION ...)` 维持既定口径：**git tag 是版本权威**。

## 8. 已知问题（本次未修）

- **GPU `stable=f16` 训练 loss 打印冻结（未修）**：`text_train --precision-stable f16` 时 step 恒 4.0137、跨 epoch/跨进程逐位相同；**权重照常更新**（冻结仅在 loss 回读链）；CPU 同配置健康；ctest 21/21 全绿但**无 GPU + stable=f16 用例**。触发矩阵与证据见 [`14-f16-stable-gpu-loss-frozen.md`](../development/14-f16-stable-gpu-loss-frozen.md)。**推荐路径 `--f16`（stable/optimizer=f32）实测健康。**
- **数值性限制**：四字段全 f16 不可训练——`optimizer=f16` 单独即令 Adam 更新爆炸，`stable=f16` 链约 200 步 NaN（见 [`05-mixed-precision.md`](../development/05-mixed-precision.md) §12.5）。
- **`text_train` 跨进程不可复现**：数据洗牌 RNG 仍为 `mt19937_64{random_device{}()}`（属运行期随机性，不迁 InitSpec）；当前无数据洗牌种子 CLI 参数。
- **库外残余不确定性**（§4）：25 条 dry-run-only 结构无法先验覆盖，预案 `COLLECT <file>` 钩子。
- **Windows 上 LeakSanitizer 不可用**：本轮内存验证（ASan/UBSan）覆盖 use-after-free / 越界 / 未定义行为，**不含泄漏检测**。
- **GPU dev1（MESA/D3D12 转译）不可用**：初始化即报 DXIL container 校验错误（设备级问题，非库问题，见 [`16-computeengine-p0-inventory.md`](../development/16-computeengine-p0-inventory.md)）。
