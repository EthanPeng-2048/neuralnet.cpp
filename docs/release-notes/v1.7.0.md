## 1. 统一数据格式

### 1.1 KVRecord v2（`model_keyvalue_record.hpp`）

- **v2 布局**：`[field_count u32]`（含哨兵）+ 哨兵内联字段 `kvrec_version=2` + 字段头（key / type / **addr u64**）+ 数据块（`[value_len u64][value]`，按字段序连续排布）。
- **版本自举**：field[0] 按 v1 布局读出——key == `kvrec_version` ⇒ v2，否则 v1（"无版本字段 = v1，有 = 按版本读"）。**模型 spec header 继续 v1，字节零变化。**
- **嵌套**：`Type::Record = 3`，值 = 完整嵌套 v2 kvrec 字节（含自身哨兵），addr 为文件绝对偏移——`.nndataset` 的 companion / train / test / vocab 层层嵌套全靠它。
- **向前兼容**：未知类型按长度安全跳过（沿用 v1 承诺）。
- **搬迁防护**：解析器校验每个数据块 `addr == 期望游标`——换基址整体复制的字节（地址失效）**硬报错**，不会静默读到错值。

### 1.2 `.nnvocab` 词表文件（kvrec v2）

- `[label "NNVC" + file_version=1][词表 kvrec v2]`；字段 `type`（`"bpe"` / `"char_bpe"`）、`vocab`（词表 blob，token 原样字节）、`merges`（展平三元组）、`markers`（对话标记 ID 8 元组，可缺省）。
- **旧 JSON 词表不再直读**：加载报错并指路 `dataset_convert vocab`（§6 迁移）。

### 1.3 `.nndataset` 数据集文件

- `[label "NNDS" + file_version=1][文件级 kvrec v2][doc 块 arena]`：
  - companion 三层嵌套：**vocab**（词表 kvrec）/ **source**（路径、**内容 sha256**（新增 `core_sha256.hpp`）、文档数）/ **license**（纯文本文档，可缺省）/ **gen**（`loss_scope`、工具、时间戳）；
  - train / test 子集：`num_docs` + `doc_index`（`num_docs+1` 个**文件绝对偏移**）寻址 doc 块；
  - doc 块 = `[token_count u64][token_count × u64 tokens][token_count × u8 loss_mask]`（token 存 u64，逐位同构旧 `size_t` 路径）。
- **体积实施**：`loss_scope=all` **不写 mask 段**（全 1 是纯冗余），加载端按 `gen.loss_scope` 合成——语义等价。
- **doc_id 不存储**：= doc 在子集中的序号 + 1，加载端按 `doc_index` 顺序重建（含空 token doc 不丢行号）。

## 2. `nn::Dataset` 与生成/转换工具

- **`nn::Dataset`**（`dataset.hpp`，只读）：`open()` 嗅探标签分派 `.nndataset`/`.nnvocab`，`info()` 元数据视图，`load_text([test])` 一次给出 `(token_flow, doc_ids, loss_mask)`——与旧 tokcache + `mark_assistant_spans` 产物**逐位同构**。不做窗口化（窗口是训练策略，仍归 `text_train` 的 `--seq-len`/`--stride`）。
- **生成期公共件**（与 `dataset_gen` 共用、可单测）：`read_text_docs`（行 trim 规则）、`encode_docs_parallel`（保序并行 tokenize）、`mark_assistant_span`（逐 doc 掩码）——三段逻辑**逐字**迁自 `text_train`（§8 一致性硬约束）。
- **`dataset_gen`**（新 CLI）：`文本 + .nnvocab → .nndataset`，`--test`（第二输入 → test 子集）/ `--loss-scope all|assistant`（语义在生成期定）/ `--license` / `--source`。
- **`dataset_convert`**（新 CLI）：`vocab <in.json> -o <out.nnvocab>`（旧词表迁移）；`csv` 子命令为阶段四预留（尚未实现，明确报错）。

## 3. `text_train` 切换与模型格式 v6

- 位置参数 `<text-file>` → **`<dataset.nndataset>`**；**移除 `--vocab` / `--test-file` / `--loss-scope` / `--no-cache`** 四选项，词表 / loss 掩码 / test 子集全随数据集；`--seq-len` / `--stride` 窗口化保留。
- 删除清单：txt 直读（`read_file_lines`）、内联并行 tokenize（`parallel_tokenize`）、assistant 掩码扫描（`mark_assistant_spans`）、**`.tokcache` 整套机制（作废，可直接删除旧缓存文件）**。
- 保存模型时内嵌词表 = 数据集配套词表 kvrec（`.nnvocab` 文件镜像字节）；**`MODEL_VERSION 5 → 6`**。
- **读取按版本分派**：v5 及以下读其内嵌 JSON（模型格式的一部分，照常读取）、v6 起读内嵌 kvrec——旧模型零破坏、不需要模型转换工具。`load_model` 新增可选出参 `version_out` 供分派。
- ⚠ 版本号抢号提示：roadmap P1-2（checkpoint 优化器状态）也计划 `5 → 6`，谁后落地谁顺延（已在 `model_serialization.hpp` 记录）。

## 4. 错误处理宏族（易用性）

- `core_errors.hpp` 三种语义 + 错误源头糖：传播 `NN_TRY` / `NN_TRY_MSG` / `NN_TRY_CHECK`、解包+终止 `NN_CHECK(expr[, "语境"])`、解包+退出码 `NN_EXIT(expr, code[, "语境"])`、`NN_FAIL("msg")`；终止策略只有 abort/exit（`-fno-exceptions` 全程无 `throw`）。
- **存量迁移全部完成**：`src/` 退出样板 320 处 → `NN_EXIT`；全仓传播/错误源 1209 → 0（脚本迁移 + 两阶段人工审边缘形态），门禁 = `doc_inventory.ps1` 第 [5] 节**基线 0**。
- 同批交付**按需薄转发头** `engine.hpp` / `layer.hpp` / `loss.hpp` / `optimizer.hpp` / `model.hpp` / `train.hpp`（`nn.hpp` 仍是唯一聚合头）。

## 6. 破坏性变更与迁移指南

### 6.1 迁移三步（旧资产 → v1.7.0）

```bash
# 1) 旧 JSON 词表 → .nnvocab（一次性）
./build/dataset_convert vocab old_bpe.json -o old_bpe.nnvocab

# 2) 文本语料 → .nndataset（token/掩码在生成期定好；对话 SFT 用 --loss-scope assistant）
./build/dataset_gen corpus.txt --vocab old_bpe.nnvocab -o corpus.nndataset
./build/dataset_gen dialogs.txt --vocab old_bpe.nnvocab -o dialogs.nndataset \
    --loss-scope assistant --test dialogs_eval.txt

# 3) 训练（词表/掩码/test 子集随数据集，不再是选项）
./build/text_train corpus.nndataset --epochs 10
```

### 6.2 CLI 变更对照

| 旧（≤ v1.6.1） | 新（v1.7.0） |
|---|---|
| `text_train <text-file> --vocab v.json --test-file t.txt --loss-scope … --no-cache` | `text_train <dataset.nndataset>`（四选项**移除**；语义随数据集，`--test-file` = 数据集的 test 子集） |
| `tokenizer_train … --output bpe_vocab.json` | `--output` 默认 **`bpe_vocab.nnvocab`**；JSON 写出废弃 |
| `text_* / tokenizer_* --vocab v.json` | `--vocab` 只读 **`.nnvocab`**；旧 JSON 报错指路 `dataset_convert`（`text_train` 上该选项整体移除） |
| `.tokcache` 自动缓存 | **作废**（生成期编码已进数据集；旧 `*.tokcache` 可删） |
| —— | 新增 `dataset_gen` / `dataset_convert` |
| 模型文件 v5（内嵌 JSON 词表） | v6（内嵌 `.nnvocab`）；**v1–v5 读取零变化** |

### 6.3 API 变更（库使用者）

- `nn::load_tokenizer_from_file` 返回 `std::unique_ptr` → **`Result<std::unique_ptr<Tokenizer>>`**（可报告"旧 JSON 不直读"等错误）；新增 `load_tokenizer_from_kvrec` / `load_tokenizer_from_bytes` / `load_tokenizer_from_model_blob(bytes, model_version)`。
- `Tokenizer::save`/`load` 改读写 `.nnvocab`；JSON **写出**废弃（`save_vocab_json_`/`write_vocab_entry_` 删除），JSON **读取** `load_from_string` 保留（模型 v5 内嵌 + 迁移器用）；新增 `to_kvrec()` / `load_from_kvrec()` / `kvrec_type_str()`。
- `nn::load_model(filename, model, uint32_t *version_out = nullptr)`（出参可选，向后兼容）。
- 新增 `nn::Dataset` / `nn::write_nndataset` / `nn::read_text_docs` / `nn::encode_docs_parallel` / `nn::mark_assistant_span` / `nn::sha256_hex` / `KeyValueRecord::serialize_v2` / `parse_at`。

## 7. v1.6.1 补记（上一版无发布说明）

`v1.6.1`（2026-10-04，83 files / +7555 / −2804）发布时未附 release note，其用户可见变化补记于此（自 v1.6.0 起）：

- **BatchNorm 真实现 + CNN/ViT 接入归一化（破坏性：默认结构变化）**：`make_norm_layer` 不再静默回落 LayerNorm；`--norm auto` 默认 = CNN `BatchNorm@conv`（86.71% → 89.48%）、ViT `LayerNorm@final`（69.00% → 77.50%）；新增 `--norm-place`。**默认结构变化会移动 init 锚**（旧模型文件仍可加载；`norm_place` 缺键 = 旧布局）。

- **text_train 旗舰开训前置三选项** + `scripts/` 代码/数学语料下载脚本。
- 修复 `NN_EXPR_SCAN` 下 `fused_registry` 的 depfile 依赖环（守卫改嵌套 `#ifndef`）。

## 8. 已知问题（本次未修）

- **GPU `stable=f16` 训练 loss 打印冻结（未修）**：`text_train --precision-stable f16` 时 step 恒 4.0137、跨 epoch/跨进程逐位相同；**权重照常更新**（冻结仅在 loss 回读链）；CPU 同配置健康；ctest 27/27 全绿但**无 GPU + stable=f16 用例**。触发矩阵与证据见 [`14-f16-stable-gpu-loss-frozen.md`](../development/14-f16-stable-gpu-loss-frozen.md)。**推荐路径 `--f16`（stable/optimizer=f32）实测健康。**
- **数值性限制**：四字段全 f16 不可训练——`optimizer=f16` 单独即令 Adam 更新爆炸、`stable=f16` 链约 200 步 NaN（见 [`05-mixed-precision.md`](../development/05-mixed-precision.md) §12.5）。
- **`text_train` 跨进程不可复现**（沿袭 v1.6.0；本轮基线取证再次实测确认）：同配置连续运行 loss 轨迹与保存模型哈希两两不同，根因未定位（数据洗牌 RNG `mt19937_64{random_device{}()}` 是已知随机源之一）。数据等价判据因此落在 `dataset_test` 的逐位对拍与确定性探针锚上，详见 [`history.md`](../history.md)「统一数据集」条。
- **`.nndataset`/`.nnvocab` 的 v2 地址为文件绝对偏移**：嵌套 kvrec 字节**不可整体搬迁**到别的文件（换基址复制会被连续性校验抓住并报错）；需要搬迁时按字段表重建 addr（留作扩展）。
- **`dataset_convert csv` / tabular 形态未实现**（阶段四预留，调用即明确报错）；DataLoader / 流式加载未做（`load_text` 一次性物化大语料会占内存，见 [`18-roadmap.md`](../development/18-roadmap.md) P2-4 后半）。
- **库外残余不确定性**（v1.6.0 遗留）：25 条 dry-run-only 融合结构无法先验覆盖，预案 `COLLECT <file>` 钩子。
- **Windows 上 LeakSanitizer 不可用**；**GPU dev1（MESA/D3D12 转译）不可用**（设备级问题）。
