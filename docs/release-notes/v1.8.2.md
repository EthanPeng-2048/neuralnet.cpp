# neuralnet.cpp v1.8.2 Release Notes

> **发布范围**：`v1.8.1`（`830091f`，2026-10-12）→ `v1.8.2`。
> **主题**：**f16 训练缺陷修复（F1–F5，含"四字段全 f16 可训练"）** + **f16 提速（编译期精度特化 / 批量派发 / 网格粒度变体 / F16C / f16 GEMM）** + **RAPT / CNN 的 f16 接线** + **`Layer::init` 参数精度自检**。
> **兼容性**：**无破坏性 API 变更**——引擎接口与 virtual 计数（52）不变、`get_*_spirv()` 名称/签名不变、`create_tensor` 签名保留；仅新增可选字段/函数与一处 **init 期 fail-fast 收紧**（见 §4 与 §6）。逐条核验见 [`../todo/24-f16-training-defects.md`](../todo/24-f16-training-defects.md)（缺陷台账）与 [`../todo/26-f16-speedup-plan.md`](../todo/26-f16-speedup-plan.md)（提速方案）。

## 1. f16 训练缺陷修复（[`24`](../todo/24-f16-training-defects.md) F1–F5）

- **F3 修 GPU `stable=f16` loss 冻结**：真因**不是** loss 回读链，而是 CE 的 `(1,1)` loss 归约**输出按 `p_.stable` 落盘溢出**（`compute_loss.hpp` 的稠密与稀疏 `fused_forward_sparse_` 两条链）。修法 = 该 `(1,1)` 归约输出**恒 `Precision::F32`**。实测（850M）：`seq256/b32` 由 `inf` → `9.0056 → 8.6922`；`stable=f16` 120 步无 NaN。回归用例见 `f16_precision_test` / `ce_fusion_test`。
- **F5 全 f16 可训练**：不用训练循环 loss scaling，而是在**优化器状态更新处缩放**（`Adam::optimizer_state_scale_`）——进入 `m/v` 的梯度放大 `S=4096`（2 的幂 → f16 下无损），`(1-β1)·S` / `(1-β2)·S²` / `eps·S` 同步换算。**为什么有效**：Adam 更新是尺度不变的 `lr·(S·m̂)/(√(S²·v̂)+S·eps) = lr·m̂/(√v̂+eps)` ⇒ 更新量数学不变，但 `m~g·S`、`v~g²·S²` 都回到 f16 正常区。边界：`|g| ≳ 0.0625` 时 `v` 会溢出 f16 ⇒ 实践配 `--max-norm` 裁剪。
- **F1 危险精度组合启动期告警**：新增 `include/neuralnet.cpp/cli/cli_precision_warning.hpp`（`nn::cli::dangerous_precision_warning`），`text_train` / `mnist_train` 在解析后、进训练循环前打印一次到 stderr；触发 = `optimizer=f16`（覆盖四字段全 f16）。**仅警告**：不退出、不加确认开关、退出码与训练行为不变。门禁 `src/cli_precision_warning_test.cpp`（单测组合矩阵 + 子进程捕获 stderr）。
- **F2 覆盖缺口**：profile 组合矩阵补 `{F16,F16,F16,F16}` 行；`stable=f16` / 全 f16 形态进 GPU 分支做数值断言；CE 溢出回归。端到端全 f16 训练仍归**大版本发布清单**（[`25`](../todo/25-release-requirements.md) 第 1 项，不进默认 ctest）。

## 2. f16 提速（[`26`](../todo/26-f16-speedup-plan.md)；台账 24 · F4）

验收锚 = **任意设备**（含无 `shaderFloat16` 的 850M）`--f16` step ≤ f32 且峰值显存更低。落地四件（另有一件 S3）：

- **P2-11 编译期精度特化**（`#s` = 全 f16 静态签名 / `#xxxx` = 扫描期真实观察到的签名）：把"精度是运行期参数"（`#x` + PC `prec`）在热路径换回"精度是编译期常量"，**只需 16 位存储、不依赖 `shaderFloat16`**。850M：`--f16` 2260 → **2055 ms/15 步**（f32 2037，+10.6% → **+0.9%**）。
- **P2-13 网格粒度变体**（`#f`/`#ks`/`#kr` 叠加到精度签名）：每个静态签名变体各发一份；**部分和缓冲恒 f32**（末段按 sig 落盘）。40HX（b64）该 wgrad **f16 16.0 vs f32 25.1 ms/块**；端到端 40HX **1013 vs 1027 ms（−1.4%）**、850M（b16）**2005 vs 2038 ms（−1.6%）**。
- **P2-12 优化器 f16 批量派发**（`#b`）：对每个 extras 为空的静态签名变体各发一份批量变体；残差根因 = **scan 与运行期不同源**（已修）。实测（40HX）：`[ir-c][degrade]` **70 → 0 / 步**、优化器派发 **138.7 → 8.55 calls/步（−94%）**、host 阶段 **9.94 → 6.51 ms/步**；端到端墙钟在 GPU-bound（忙率 95.5%）下不可测。
- **P2-8 / S4 CPU F16C 转换**：`detail::float_to_half_bits` / `half_bits_to_float` 增 `__F16C__` 快路径（`_cvtss_sh`/`_cvtsh_ss`，imm8 = `_MM_FROUND_TO_NEAREST_INT` → 与 MXCSR 无关、恒 RNE）；**常量求值**与 `NN_ENABLE_NATIVE=OFF` 可移植构建仍走软件位操作。`precision_test` 增「软/硬逐位一致」段（23 条 f32→f16 + 15 条 f16→f32）。
- **S3 f16 GEMM**（storage-only、f32 累加）：`-DNN_SHADER_F16=1` 编第二份 SPIR-V；小 N（`N ≤ 8` 且 `transA=0`）走 `matmul_q_gemv.comp`。
- **已评估-不做**（均附实测/上界证据，见 [`26`](../todo/26-f16-speedup-plan.md) §4）：**S0**（step 内固定开销——前提被实测推翻）、**S1**（主导张量全 f16——实测净亏）、**S2**（f16x2 打包）、**S5 / P2-10**（native16 资格不再扩大——收益有界）。

## 3. RAPT / CNN 的 f16 接线（roadmap P2-3）

- **RAPT**：**27 处** `dsl::compute*` 补精度实参 `p_.compute`（此前全部落默认 F32）；两个残差分支由硬编码 `Precision::F32` 改 `p_.compute`；`token_emb_`/`grad_token_emb_` 改 `p_.param`；`rms_norm_forward_/backward_` 的输出改 `p_.compute`（否则 dst/src 精度错配 → `insert_rows` 断言）。
- **Conv2D**：`w_`/`b_`/`grad_w_`/`grad_b_` 改 `p_.param`，4 处 `dsl::compute*` 补 `p_.compute`。
- **API**：`CnnConfig` 增 `precision` 字段（默认 `PrecisionProfile{}` = 全 F32），`build_cnn_model(_from_spec)` 在 `add` 之前注入（新增可选形参）。
- **门禁**：新增 4 条 ctest —— `cnn_test_f16` / `cnn_test_f16_gpu` / `rapt_test_f16` / `rapt_test_f16_gpu`（断言 loss 有限且下降、梯度无 NaN；GPU 侧另验精度变体闭合世界与槽位）。

## 4. `Layer::init` 参数精度自检（P1-6 R2；行为收紧）

`Layer::init`（NVI）在 `init_impl` 之后统一执行 `check_param_precision_()`——层声明的 `param` 槽是**存储精度**时，逐个校验 `parameters()` 的张量实际存储精度与之相同（`precision_bytes(p_.param) == 0` 的非存储精度声明，如 `T1_58`，跳过）。

它防的是一类**静默降级**：层把权重/梯度硬编码 F32（或忘用 `p_.param`）→ `--f16` 下该层参数仍是 f32，训练照跑、数值不错，但"f16 省字节"在其上完全落空。**当场抓到 3 处**：Conv2D 的 `w_/b_`、RAPT 的 `token_emb_`、`ReLULinearAttention` **从未把 profile 转发给它自持的 4 个 `Linear`**（RAPT 注意力投影权重在 `--f16` 下一直是 f32）——前两处在 P2-3 修掉，第三处由本自检报错后发现并修复。

> **迁移提示（写自定义层的人）**：若你的层声明了 `PrecisionProfile.param` 为某种**存储精度**（f16/f32），但把参数张量硬编码成另一种，`init` 现在会**报错**（此前静默通过）。修法 = 参数创建时用 `p_.param`。指南见 [`../development/write-a-custom-layer.md`](../development/write-a-custom-layer.md)。

## 6. 兼容性说明

- **无破坏性 API 变更**：引擎 virtual 计数 **52** 不变；`get_*_spirv()` 名称/签名不变；`create_tensor` 签名保留；`Layer`/`Loss`/`Optimizer`/`Model` 公共入口无删除。
- **新增（可选）**：`nn::cli::dangerous_precision_warning`；`CnnConfig::precision`（默认全 F32）；`build_cnn_model_from_spec(engine, spec, precision = PrecisionProfile{})` 可选形参；`profile_all_f16()`。
- **行为收紧（1 处）**：`Layer::init` 新增参数精度自检（§4）——库内层全部自洽；**自定义层**若声明 `param` 为存储精度却把参数硬编码为另一精度，会在 `init` 报错（此前静默降级）。
- **数值**：默认（f32）路径与 v1.8.1 **逐位一致**（`param`/`compute` 默认 F32 不变）；`--f16` 的数值路径随新增特化/网格变体 shader 改变（**同语义、不同 kernel**），如出现旧 `--f16` 字节锚差异属预期。
