# AttnZip（ZiPT）：记忆压缩解码器算法设计

> 本文档定义 AttnZip 算法及其在项目中的实现（ZiPT），一种通过可学习"记忆查询向量"将长上下文压缩为少量信息 Token 的注意力算法。核心设计直达极简主义：摒弃复杂门控与状态递推，仅用标准 Softmax 的归一化特性分配注意力预算，从而对长上下文实现线性复杂度，并完美兼容 FlashAttention 等硬件加速技术。

---

## 1. 引言与设计哲学

标准 Transformer 的自注意力机制具有 O(L²) 的计算与内存复杂度，是长上下文建模的主要瓶颈。为此学术界提出了大量线性注意力、状态空间模型（SSM）以及带复杂门控和卷积机制的变体。然而，这些方法往往引入大量工程补丁（如时变门控、短程卷积、Delta Rule 等），导致算法表达式臃肿，失去了 Transformer 原本"大道至简"的数学美感。

**AttnZip** 回归极简主义。算法摒弃所有复杂门控与状态递推机制，仅通过引入一组可学习的"记忆查询向量（Memory Queries）"，利用标准 Softmax 的归一化特性来分配注意力预算，从而将长上下文无损或有损地压缩为少量"信息 Token"。它在保持表达式极度简洁的同时，实现对长上下文长度的线性复杂度，并完美兼容 FlashAttention 等硬件加速技术。

## 2. 核心动机

1. **拒绝"缝合怪"设计**：不使用 LSTM 式门控或 Mamba 式复杂状态更新，保持核心算子仅为标准的矩阵乘法与 Softmax。
2. **Softmax 即重要性分配器**：Softmax 的本质是概率分布（行和为 1）。引入 M 个查询向量后，模型天然获得 M 个"注意力预算"，自动将高权重分配给重要 Token、低权重分配给无用信息，从而实现基于重要性的信息压缩。
3. **隐变量而非显式文本**：压缩后的信息 Token 是连续的隐变量（Latent Variables），作为全局记忆供后续网络读取，无需还原为离散文本，避免自编码器带来的额外计算开销与信息损失。

## 3. 算法公式与流程

### 3.1 符号定义

- L：真实长上下文的序列长度。
- M：压缩后的记忆 Token 数量（Bottleneck Size），且 M ≪ L。
- W：局部窗口大小（Local Window Size）。
- d：模型的隐藏层维度。
- `X ∈ R^{L×d}`：输入的长上下文隐藏状态。
- `P ∈ R^{M×d}`：**可学习的记忆查询矩阵**（Memory Queries），本算法唯一引入的额外参数。

### 3.2 阶段一：全局上下文的重要性压缩

此阶段将长度为 L 的上下文压缩为长度为 M 的信息 Token。

首先计算长上下文的 Key 和 Value：

```
K = X W_K,   V = X W_V
```

其中 `K, V ∈ R^{L×d}`。

接着，使用可学习的记忆查询矩阵 P 作为 Query，对 K 和 V 进行交叉注意力（Cross-Attention）计算：

```
A = Softmax( P K^T / sqrt(d) ) ∈ R^{M×L}
C = A V ∈ R^{M×d}
```

**原理解析**：矩阵 A 的每一行都是和为一的概率分布，M 行的总权重和为 M，相当于模型在 L 个 Token 中分配了 M 个"注意力预算"。重要性高的 Token 获得更大权重，其 Value 更多聚合到 C 中；无用信息被忽略。C 即压缩后的**信息 Token（Memory Tokens）**。

### 3.3 阶段二：局部-全局联合注意力

在后续的 Transformer 层（或文本生成阶段），当前 Token 需同时利用全局记忆 C 和局部细节 `X_local`。

设当前局部输入的隐藏状态为 `Y ∈ R^{W×d}`，计算其 Query / Key / Value：

```
Q_y = Y W_Q,   K_y = Y W_K,   V_y = Y W_V
```

计算全局记忆的 Key 和 Value（可复用阶段一的 C 经线性变换，或重新计算）：

```
K_c = C W_K,   V_c = C W_V
```

将全局记忆与局部上下文在序列维度拼接：

```
K_cat = [K_c, K_y] ∈ R^{(M+W)×d}
V_cat = [V_c, V_y] ∈ R^{(M+W)×d}
```

执行标准自注意力：

```
O = Softmax( Q_y K_cat^T / sqrt(d) ) V_cat ∈ R^{W×d}
```

## 4. 复杂度与显存分析

### 4.1 计算复杂度（FLOPs）

- **阶段一（压缩）**：计算 `P K^T` 和 `A V`，复杂度 O(M·L·d)。M 为常数且 M ≪ L，此项对 L 为**线性复杂度 O(L)**。
- **阶段二（联合注意力）**：计算 `Q_y K_cat^T`，复杂度 O(W·(M+W)·d)。M、W 均远小于 L，此项对 L 为**常数复杂度 O(1)**。
- **总体**：O(M·L·d + W·(M+W)·d)。处理超长上下文时复杂度完全由 O(L) 主导，彻底消除 O(L²) 瓶颈。

### 4.2 内存/显存复杂度

- 传统 Attention 需要实例化 L×L 注意力矩阵，显存 O(L²)。
- 本算法中，阶段一注意力矩阵大小为 M×L，阶段二为 W×(M+W)。
- 结合 **FlashAttention** 技术，算法通过分块（Tiling）与重计算（Recomputation）避免在 HBM 中显式实例化这些注意力矩阵。
- **峰值显存**：仅需保存 K、V 激活值（O(L·d)）及极小注意力分块，显存开销对 L 呈**线性**，完美支持百万级上下文。

## 5. 信息流转：从隐变量到文本生成

一个常见疑问："信息 Token C 压缩了上下文，它如何被还原成文本输出？"

**答案是：信息 Token 不需要被还原成文本。**

1. **隐变量本质**：C 是一组连续高维向量，代表模型的"长期工作记忆"。它不是离散文字，而是语义和事实的稠密表示。
2. **文本生成路径**：文本生成由模型最后的语言模型头（LM Head）完成。自回归生成时，Decoder 的当前隐藏状态 h_t 通过阶段二的注意力机制读取 C。
3. **输出映射**：融合了全局记忆 C 的隐藏状态 h_t 经过 FFN 和 LayerNorm 后，直接经线性层映射到词表空间：

```
logits_t = h_t W_vocab
p(y_t)   = Softmax(logits_t)
```

换言之，C 只是为文本生成提供**条件（Condition）**与**上下文（Context）**。模型根据 C 中的记忆直接组织语言输出，无需经历"压缩 → 还原原文 → 生成答案"的冗余过程。

## 6. 算法优势与局限性分析

### 6.1 核心优势

1. **极致的数学美感**：核心算子仅为标准 Attention，无门控、无卷积、无复杂递推，代码实现极简，易于理解和调试。
2. **硬件友好**：完全兼容 FlashAttention、PagedAttention 等现有底层优化，无需编写复杂自定义 CUDA Kernel。
3. **可解释性强**：通过可视化阶段一的注意力矩阵 A，可清晰观察模型认为长上下文中哪些 Token"重要"，具白盒特性。
4. **灵活的容量控制**：通过调整 M 大小，可在"记忆容量"与"计算开销"间平滑 Trade-off。

### 6.2 局限性与应对

1. **有损压缩**：因 M ≪ L，极端长尾细节（如"第 83721 个词是什么"）可能在压缩中丢失。
   - 应对：保留局部窗口 W（如最近 4k Token 不压缩），确保短期精确信息不丢失。
2. **重要性评估的滞后性**：阶段一压缩时，模型可能无法预知未来问题需要哪些细节。
   - 应对：在多层 Transformer 中每隔几层重复执行阶段一压缩，让不同层级的 P 学习不同抽象层级的记忆。

## 7. 总结

AttnZip 证明了：在追求长上下文 O(L) 复杂度的道路上，并不一定要依赖复杂门控和状态递推。通过回归 Softmax 的归一化本质，利用可学习的 Memory Queries 进行重要性压缩，完全可以在保持 Transformer 极简美学的前提下实现高效的长上下文建模。
