### P0-2 → 降级 P1：Row 操作数按 spec 上下文分化语义（双端一致，当前无活跃 bug，契约文档缺陷）

**复核结论：语义差异属实，但不是实现 bug——CPU 与 GPU 双端一致，当前所有使用点语义正确。** 真正的问题是 DSL 文档契约（"batch 内"）与纯网格行为不符，属潜在陷阱。

证据链（已逐处 read 确认）：
- GPU 归约 kernel `expr_glsl_gen.hpp:935-936`：`Row: mm ? "float(row % m_per)" : "float(row)"`
- GPU matmul 尾链 `:295-296`：`float(row)`，但 main 传入的 `row` 参数即 batch 内行号（:454-464 注释 + `eval_tail(mm, row, col, batch)` 签名）
- GPU 纯逐元素 `:544-545`：`float(row)`（row = 网格全局行号）
- CPU `compute_cpu_engine.hpp:1371-1372, 1446-1447`：统一 `r % m_per`；关键在 `:1088-1089`：`m_per = (mm && batch>0 && rows%batch==0) ? rows/batch : rows` —— **纯 spec 下 m_per=rows，故 `r % m_per == r`**，与 GPU `float(row)` 行为完全一致
- 当前使用点核对：① attention causal 掩码（compute_layer_attention.hpp:223-255 `col() > row()`）走 matmul+行归约路径 → batch 内行号 ✓ 正确；② CE 稀疏 `row() == col_broadcast(labels)`（compute_loss.hpp:354）走纯逐元素路径，(vocab, total) 网格无 batch 维度 → 全局行号 ✓ 正确

**风险**：未来 Layer 若在**纯逐元素/纯归约** spec 中于展平的 (batch·seq) 网格上写 causal 类掩码（`col > row`），会拿到全局行号 → batch>1 时跨样本错误（铁律 5 灾难级），且 CPU/GPU 一致地错（交叉验证测不出）。

**建议**（三选一，按成本升序）：
1. 修正契约文档：`expr_dsl.hpp:243`、`expr_spec.hpp:535` 的 "batch 内行号" 改为"matmul spec 下为 batch 内行号；纯网格 spec 下为当前网格行号（无 batch 概念）"，并在 `expr_glsl_gen.hpp:933` 处注释中反向引用；
2. `validate_expr_spec` 增加诊断：纯 spec 中 Row 操作数 + 网格列数为 seq 的整数倍时警告；
3. 拆分为两个操作数 kind（`Row` 全局 / `RowInBatch` batch 内），attention 改用后者——彻底消除二义性，代价是 DSL/IR/key 改动。
